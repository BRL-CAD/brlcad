== NAME
db - Provides an interface to a number of database manipulation routines.

== SYNOPSIS

[source]
----
db {command} [arguments]
----


[[description]]
== DESCRIPTION

Provides an interface to a number of database manipulation routines. Note that this command always operates in units of millimeters. The _command_ must be one of the following with appropriate arguments:


__adjust shape_name attribute new_value1 [new_value2 new_value3...]__::
Modifies the shape named __shape_name__ by adjusting the value of its _attribute_ to the __new_values__.


_close_::
Closes the previously opened database and deletes the associated command.


_concat_ [-h] [-t] [-u] [-c] [-s|-p] [-L] [-O] {database_file} [affix]::
Import the objects in the source database's selected model, with optional naming adjustments. The destination keeps its own history. When history is enabled, the import and any requested metadata changes publish as one undoable operation.


_find_ [-a] <objects>::
Displays all combinations that have any of the _objects_ specified as a member. By default, *db find* will only return non-hidden objects. The `-a` option will include hidden objects. 


__form object_type__::
Displays the format used to display objects of type __object_type__.


__get shape_or_path [attribute]__::
Returns information about the primitive shape at the end of the __shape_or_path__. If a path is specified, the transformation matrices encountered along that path will be accumulated and applied to the leaf shape before displaying the information. If no _attribute_ is specified, all the details about the shape are returned. If a specific _attribute_ is listed, then only that information is returned.


__history enable session [bytes]__::
Start history for the open writable DB5 file on a platform that supports atomic replacement. Supported editing commands include `make`, `adjust`, `mvall`, `concat`, and `title`. Each `killrefs`, `killall`, or `killtree` edit has one Undo entry for its object and reference changes. Their `-n` previews also work on read-only databases. Edits save to the file as they complete, and closing the database discards the undo journal. The default journal limit is 64 MiB. When older revisions reach the limit, history may prune them. An individual edit beyond the limit fails before saving.


__history enable [embedded]__::
Persist history in the open writable DB5 file. The file stores its selected model and history together, and reopening loads the saved history automatically. A session journal, if present, is promoted with its retained branches and redo choices. MGED records accepted edits, and QGED provides Undo, Redo, and revision inspection in the Edit menu.
+
For a DB4 file, run `dbupgrade legacy.g new.g` from a terminal. Open `new.g` and enable history there. The conversion keeps the original file available.


__history status [--json]__::
Report the active history mode and available undo and redo operations. Session history reports the oldest retained revision and journal usage. Embedded history reports the selected revision, archive status, and access state. Workspace history reports the revision open in this document, its generation, and the last exported revision and export time when available. If another writer advances the workspace, status reports both the open revision and the current head. If an external editor changes a DB5 model independently of its embedded archive, GED permits inspection and protects the file from further edits.
+
Use `--json` for a structured status object with schema version 1. Revision IDs are strings. `last_export_time` is in Unix seconds. Optional values are null when unavailable. `undo` is a single action or null, and `redo` is an array of actions. Actions report the destination revision, the operation label, and whether the child is preferred. Applications can query the same state using `ged_history_status_create` from `ged/history.h`.


__history workspace directory__::
Create a durable workspace in a new directory and switch to it. The workspace imports the open DB5 model and any retained session or embedded history. Subsequent edits save to the workspace. Reopen it with `db open directory`. The source file remains available. Run this command with the open workspace's path to report its status, or specify a new directory to copy it using the current workspace schema.
+
If the editor cannot reopen the created workspace or another writer changes it before the switch, the source stays open. The command reports the created path so you can inspect it or switch to it explicitly.
+
The destination name must stay available until publication. If another process creates a file or directory there first, it keeps the name and the import fails. If the parent directory cannot be synchronized after publication, the command reports the published path and keeps the source open.
+
Close all open views before moving or replacing a workspace or its LMDB files. If the editor detects that those files changed identity, it reports the workspace as unavailable and refuses further edits. A pinned view can still read the model it opened.


__history log [--object name] [--json]__::
List retained revisions, including alternate branches. The optional name filter lists only revisions that changed that exact object name. An unfiltered embedded or workspace log also lists saved marks.
+
The schema version 1 JSON result contains `revisions` and `checkpoints` arrays. Each revision includes `id`, `parent`, `label`, `authored` in Unix seconds, `selected`, and `retention_boundary`. Each checkpoint contains a `name` and a `revision` ID.


__history show revision [--json]__::
List the records created, deleted, or updated by a single revision. A recorded rename also shows the old and new names together. Changed references appear in the same revision.
+
The schema version 1 JSON result contains `revision` and `changes`. Change entries report `type`, `name`, and `new_name` for a rename. Rename entries are followed by the underlying record changes.


__history checkout revision__::
Restore the database to any retained revision. Use `db history log` to find its ID. In embedded and workspace history, a unique ID prefix or a mark name can select a revision.


__history diff first second [--object name]__::
List the records created, deleted, or changed between two retained revisions. Use `--object` to limit the result to an exact object name.


__history mark name [--move]__::
Name the selected embedded or workspace revision for later inspection or checkout. Use `--move` to update an existing mark.


__history export path [--with-history]__::
Write the open model to a new DB5 file. A plain export omits the recognized history archive and can recover geometry after an external edit or archive error. `--with-history` includes the retained session, embedded, or workspace history. An exported file and the workspace can then evolve independently. The destination must be a new path.


__history verify__::
Check the retained history's bytes, revision graph, and object records, then compare the live DB5 model or workspace directory with the selected revision. This command also verifies the in-memory session journal and its retained branches. A valid embedded archive with external model changes reports a mismatch.


__history conflict [export path]__::
Inspect an edit retained after a stale-writer conflict. Use `export path` to save the staged revision to a new DB5 file. Embedded and workspace exports include retained history. Session exports are plain DB5 and require the original records to still be readable through their open handle. In QGED, choose *Save Staged Edit As* from the File menu. Reopen the source to load its current state and discard the staged edit.


__history prune --keep revisions [--drop tip]... [--apply preview]__::
Preview workspace history retention. Keep up to the specified number of revisions, including the anchor, along the parent path of the selected revision, each marked or reader-pinned revision, and each remaining branch tip. Use `--drop` to release an abandoned branch tip. The selected, marked, and reader-pinned revisions stay available.
+
The preview reports the expiring revisions, their artifact payload size, and the resulting retention boundaries. Repeat the options with `--apply` and the preview token to publish the change. A changed plan requires a new preview. Undo stops at a retained boundary. LMDB reuses reclaimed pages for subsequent writes. Copy the workspace to a new directory to reclaim file space or to upgrade a schema 1.0 workspace for pruning. Pruning requires local advisory file locks.


__history adopt [--apply]__::
Preview live DB5 records changed by an external writer. `--apply` records those changes as one revision whose parent is the archived selection. Adoption requires a writable database and an intact archive. Undo restores the archived model that preceded the external edits.


__history batch label commands__::
Run a Tcl list of GED argument lists as one edit. A command failure or a request for interactive input aborts the batch. For example, `db history batch {Create assembly} {{make body.s sph} {g assembly.c body.s}}` creates a primitive and its group in one revision.


__match [regular_exp]__::
Returns a list of all objects in that database that match the list of regular expressions.


__open [-r] path__::
Open a DB5 file or a workspace directory. Use `-r` to inspect, compare, or export revisions with read-only access.


__put shape_name shape_type attributes__::
Creates shape named __shape_name__ of type __shape_type__ with attributes as listed in _attributes_. The arguments to the _put_ command are the same as those returned by the _get_ command.


__redo [revision]__::
Restore a retained child of the selected revision. After Undo, Redo defaults to the child just left. Supply a revision when choosing among several branches.


_tops_::
Returns all top-level objects.


_undo_::
Restore the parent of the selected revision, including every object changed by that modeling operation.


_version_::
Print the version of the currently open BRL-CAD database.


[[examples]]
== EXAMPLES

The following examples show the uses of the *db* command to list various objects and attributes from the database, as well as to create new TGC shapes, adjust a vertex attribute, and display command formats.

.List all objects in the database that end with ".s"
====

[source,console]
----
mged> db match *.s
----
Gets a list of all objects in the database that end with .s.



====

.List all attributes and their values for _cone.s_
====
[source,console]
----
mged> db get cone.s
----

Gets a list of all the attributes and their values for shape _cone.s_.

====

.Get the value of the vertex attribute of _cone.s_
====
[source,console]
----
mged> db get cone.s V
----

Gets the value of the _V_ (vertex) attribute of shape _cone.s_

====

.Create a new TGC shape named __new_cone.s__ with specified attributes.
====
[source,console]
----
mged> db put new_cone.s tgc V {0 0 0} H {0 0 1} A {1 0 0} B {0 1 0} C {5 0 0} D {0 5 0}
----

Creates a new TGC shape named __new_cone.s__ with the specified attributes.

====

.Adjust the vertex attribute of __new_cone.s__ to a given value.
====
[source,console]
----
mged> db adjust new_cone.s V {0 0 10}
----

Adjusts the _V_ (vertex) attribute of __new_cone.s__ to the value {0 0 10}.

====

.Display the format used by the *get* and *put* commands for the TGC shape type.
====
[source,console]
----
mged> db form tgc
----

Displays the format used by the *get* and *put* commands for the TGC shape type.

====
