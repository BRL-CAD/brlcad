= Rendering BRL-CAD Models with art
:doctype: article
:toc:
:toclevels: 3

`art` renders BRL-CAD databases using Appleseed for light transport and
librt for geometry intersections.  The integration is under development.
This document records the design contract, acceptance criteria, and
verified capabilities; planned capabilities are not promises of current
support.

== Application and renderer responsibilities

* BRL-CAD owns the database, Boolean geometry evaluation, instance paths,
  region and material assignments, attributes, and database units.
* `art` translates that information into an Appleseed scene and owns the
  application workflow, asset resolution, diagnostics, and image output.
* Appleseed owns light transport, sampling, OSL shader execution, closure
  interpretation, texture services, and rendering outputs.
* bext supplies the pinned dependency stack and installation machinery.

Use public renderer and OSL APIs.  BRL-CAD geometry continues to use librt;
adding native Appleseed geometry or another intersection backend must not
change the meaning of BRL-CAD Boolean evaluation.

Material translation must preserve full instance identity and resolved
inheritance.  Object, world, camera, and shader coordinate spaces and the
conversion from database units must be explicit.  Surface orientation is
geometric information: it must not be replaced with a view-dependent normal
when crossing a renderer interface.

Keep ownership explicit for prepared geometry, per-worker librt resources,
shader groups, and renderer state.  Repeated renders must release or reuse
that state deliberately, without relying on process termination.  Share
prepared geometry only where instance transforms and material assignments
remain correct.

A requested shader, parameter, or asset that cannot be used must produce an
actionable error.  Defaults apply to unspecified inputs; they must not hide
an invalid explicit material assignment.  Unsupported features must be
reported rather than silently approximated.

== Existing implementations

The 2011 liboptical implementation (`sh_osl.cpp`, `liboslrend`, and
`render_svc`) contains examples of shader parameters, networks, hit-point
inputs, reflection/refraction, and worker state.  Its private OSL interfaces
and custom closure sampling are historical implementation details, not the
interface for a modern Appleseed integration.  Recover useful semantics and
examples as public-API implementations and regression cases.

The later `art` prototype introduced Appleseed procedural objects and read
shader names from a material object's optical `OSL` property.  OSL shading
was disabled in July 2026 after black renders and replaced with native
plastic materials.  Retest the failure using the modern dependency stack;
its historical diagnosis does not establish a general OSL limitation on CSG
or procedural objects.

Do not remove legacy user-facing behavior without identifying its
replacement and documenting any migration requirements.  Share material
representation and validation where there are actual consumers; keep
renderer-specific transport and execution in the renderer.

== Current verified baseline

The modernized dependency build has been exercised with LLVM 23.1.5, OSL
1.15, OpenImageIO 3.2, and OpenEXR 3.5.  Optional LLVM/Clang libxml2 support
is disabled.  The OSL compatibility patch also accommodates LLVM builds
that have libxml2 enabled.

== Basic rendering

A development build with Appleseed enabled can render selected database
objects with the default OSL plastic material:

----
art -a 35 -e 25 -w 640 -n 480 -P 4 -c "set samples=64" \
    -o view.png model.g all.g
----

Region colors include colors resolved through combination inheritance.
The default material is a modest specular coat over a diffuse base.  This
baseline does not yet translate every BRL-CAD optical shader or provide a
complete custom-material authoring interface.

The material graph connects `as_plastic.out_outColor` to
`as_closure2surface.in_input`.  A library material node that only returns
an output closure does not itself set the OSL surface result `Ci`.  A
controlled comparison with the modern stack produced black material
surfaces on both a native Appleseed mesh and its procedural sphere when
that terminal connection was absent; adding it restored shading on both.
The `art` regression now exercises the connected graph on librt CSG and
BOT geometry.  This identifies a wiring failure independently of any
remaining renderer compatibility or geometric-shading issues.

== Geometry boundary handling

The procedural callback receives the original geometric hit normal in object
space.  Appleseed retains that normal, the shading normal, UVs, and material
slot as intersection inputs, so copies and side changes can reconstruct
shading consistently.  The callback returns a normal facing the incoming ray
and offsets on both sides of that surface.

`art` scales its normal displacement by floating-point precision, hit-point
coordinates, and prepared object extent.  It rounds each displaced coordinate
away from the surface, following the directed-rounding approach described in
https://www.pbr-book.org/4ed/Shapes/Managing_Rounding_Error[Managing Rounding Error].
Rendering queries opt out of librt's near-origin zero snapping to preserve
the sign of entry boundaries behind an inside ray.  Boolean coalescing and
model tolerances still apply.  Positive exits close to the origin remain
visible.  The regression checks normal orientation and traces reflected and
transmitted rays to detect self-hits and skipped boundaries.  Formal error bounds from
each librt primitive and qualification near the representable feature-size
limit remain open; the rounding allowance does not establish those bounds.

The Appleseed procedural callback signature has changed.  Rebuild applications
and procedural plugins against the matching renderer headers and library.

== Geometric and shading normals

`art` passes separate normals to Appleseed.  The geometric normal describes
the actual boundary and controls surface sides and secondary-ray offsets.
Authored BOT vertex normals interpolate the shading direction independently;
a smooth appearance does not change the intersected geometry.  Both normals
receive the Boolean partition's flip when a primitive supplies a cut face.

The public librt `rt_obj_normals` query reads the original intersection
without changing it.  BOT and DSP provide separate geometric and shading
normals; other primitives use their existing normal method for both outputs.
The query rejects nonfinite or zero normals and orients the shading normal
into the geometric normal's hemisphere.  It preserves authored interpolation
without the legacy BOT/DSP clamping to the incident ray.  Existing normal
queries retain their historical behavior.

Exact tests cover smooth BOT entry and exit, nonuniform transforms, Boolean
subtraction, clockwise winding, and grazing/back-face queries.  An OSL
emission diagnostic renders the difference between `N` and `Ng` on a smooth
BOT, checking that the distinction reaches shader execution.  The same
diagnostic on a flat BOT checks that the normals agree.  DSP ray tests
also exercise repeatable queries and view-independent shading directions.
These checks do not yet qualify bump mapping, normal maps, or all light
transport cases at shading discontinuities.

The librt function table has a new optional normals callback.  Rebuild
consumers against the matching librt headers and library.

== Surface coordinates

OSL `u` and `v` come from the intersected librt primitive's native mapping.
Boolean cut faces retain the mapping of the primitive that supplied the
boundary.  Sphere and cylindrical mappings have seams, and ARB faces have
independent planar coordinates; a Boolean operation does not create a new
continuous parameterization.

BOT meshes with authored texture coordinates interpolate the per-corner
coordinates of the intersected triangle.  Separate texture indices preserve
seams.  Coordinates outside the unit square remain available for tiling.
Database transforms move the geometry without changing its authored UVs.
A BOT without authored UVs, or a primitive without a supplied mapping,
returns `(0,0)`; `art` does not generate a projection in that case.

The diagnostic emission shader in `regress-art` renders `(u,v,0)` on a
sphere, a Boolean solid, and a BOT without depending on illumination.
Exact intersection tests check coordinates and transformed instances;
`rt_bot_uv` also checks packet intersections, winding, degenerate faces,
malformed data, and ownership of prepared coordinates.  `rt_arb_uv` exercises
concurrent first-use mapping and normal queries.

These checks establish point coordinates.  Appleseed now accepts optional
object-space derivatives of position and the unit shading normal with
respect to UV.  It preserves them through copied hits and side changes,
transforms position derivatives as vectors, and differentiates both the
inverse-transpose normal transform and normalization.  Ray footprints use
the geometric surface and a double-precision UV solve.  Native renderer
tests compare normal derivatives to finite differences and check known UV
footprints, including very small and large scales with analytic inverses.
Native sphere, rectangle, and disk intersections supply their analytic
mapping derivatives; singular mappings report unavailable derivatives.

`art` fills these inputs from native librt mappings for authored BOT UVs,
spheres, and ellipsoids.  Boolean cuts reverse normal derivatives while
preserving position derivatives and UVs.  Missing or singular mappings
produce zero UV footprints, with an independent shading basis fallback,
rather than an arbitrary mapping scale.  Other primitives currently supply
point UVs only where available.

The analytic callbacks preserve the prepared UV frame, including axes
accepted within preparation tolerances.  Finite-difference tests cover
position and unit-normal derivatives, rotated frames, inside rays, and
singular poles.  Art intersection tests check the transferred derivatives
against known chart tangents and independent nearby-ray normal differences.
An OSL emission diagnostic evaluates `filterwidth(u)` and `filterwidth(v)`
in actual orthographic and perspective renders.  Spheres, ellipsoids, and
flat and smooth authored BOTs must produce finite, positive footprints.
The current ARB/TGC Boolean fixture must produce the zero-footprint fallback.
These checks establish that the mapping derivatives reach OSL.  Mipmapped
texture minification is also checked against a known reference as described
below.  Bump and normal-map shading remain unqualified.  Rebuild procedural
plugins and applications against the matching Appleseed headers and library.

Visible emission is covered by the diagnostic shader, but direct light
sampling of emissive librt surfaces and their surface-area registration are
not implemented.  Emission visibility does not establish an efficient area
light workflow or area-normalized power controls.

== Selecting an OSL material

The existing `material` command can select a compiled OSL shader for a
region.  For example, in MGED:

----
material create paint.material Paint
material set paint.material optical OSL as_plastic
material set paint.material optical OSL.output out_outColor
material assign ball.r paint.material
material get paint.material optical OSL
----

The optical `OSL` property names the shader.  For a library shader node,
`OSL.output` selects a scalar closure-color output and defaults to
`out_outColor`.  `art` connects it to `as_closure2surface`.  A shader declared
as `surface` writes `Ci` itself and must not specify `OSL.output`.

Shaders are queried through Appleseed's public metadata interface before
rendering.  Missing shaders, invalid outputs, and invalid material-object
references stop the render with an error.  The region's resolved sRGB color
is converted to linear RGB and supplied to a compatible scalar `in_color`
input, when present.  Explicit typed parameters override this color and the
compatibility defaults for `as_plastic`.

Version 1 stores typed inputs in optical properties named
`OSL.param.<input>`.  `OSL.version` can be set to `1`; omitting it retains
version 1 behavior for existing assignments.  For example:

----
material set paint.material optical OSL.version 1
material set paint.material optical OSL.param.in_color "color 0.2 0.4 0.6"
material set paint.material optical OSL.param.in_specular_roughness "float 0.35"
material get paint.material optical OSL.param.in_specular_roughness
material remove paint.material optical OSL.param.in_specular_roughness
----

Supported input types are `int`, `float`, `color`, `point`, `vector`,
`normal`, `matrix`, and `string`.  A value starts with its exact OSL type.
Triples require three components; matrices require sixteen components in
the renderer's row-major order.  Numeric components must be finite and
representable in the renderer's `int` or `float` storage.  Explicit colors
are linear RGB.  Points, vectors, and normals use the shader's common
coordinate space; no implicit unit or coordinate conversion is applied.
A string contains the remaining text after `string`, including internal
spaces; leading and trailing whitespace is trimmed.  Tcl quotes group the
property value and are not part of the stored string.

Unknown inputs, type mismatches, invalid values, output assignments,
closures, structures, and arrays stop rendering before an image is written.
Unknown `OSL.` properties and unsupported format versions also produce an
error.  Unspecified inputs retain the shader or compatibility defaults;
removing an input property restores those defaults.  The regression uses
the material command to persist and reopen every supported input type,
including a string with spaces, before checking rendered shader results.

Multi-node networks, material-object parent inheritance, and per-instance
material overrides remain planned capabilities.

Errors reported by the renderer during initialization, worker execution,
or renderer cleanup stop the render with a nonzero exit status before
saving an image or replacing an existing output.  This includes unhandled
OSL texture errors, even when
Appleseed's render status otherwise reports success.  Warnings alone do
not fail the render.  A shader may deliberately request the `texture()`
`errormessage` output and supply its own fallback; handled errors that do
not reach the renderer error log remain under the shader's control.
`regress-art` checks both missing-texture behaviors.


== Project shader assets

`art` resolves project assets relative to the database directory, including
its `shaders` subdirectory, and also searches the selected Appleseed shader
libraries.  Build-directory paths and the caller's working directory are
not part of the project convention.  Keep database-relative asset paths
when moving a project to another directory.

Shader metadata inspection follows the same ordered search paths as OSL
execution.  A same-named compiled shader in the caller's working directory
cannot supply a different interface for a project shader.  The regression
renders with such a collision and compares the result with the independent
texture reference.

For a custom surface shader, save this source as `painted.osl`:

[source,c]
----
surface painted(color in_color = color(1))
{
    Ci = in_color * diffuse(N);
}
----

Compile with the OSL compiler and standard headers from the renderer's
dependency installation.  Here `RENDERER_PREFIX` identifies that installation:

----
mkdir -p shaders
"$RENDERER_PREFIX/bin/oslc" -I "$RENDERER_PREFIX/share/OSL/shaders" \
    -o shaders/painted.oso painted.osl
----

Place the database beside the `shaders` directory.  Select the shader in
MGED, removing the closure-output property because this shader writes `Ci`
directly:

----
material set paint.material optical OSL painted
material remove paint.material optical OSL.output
----

`regress-art` compiles its diffuse shader using the selected dependency
installation and renders it on a sphere, a Boolean solid, and a BOT.  Its
project directory contains spaces and is separate from the rendering
working directory.  A second fixture returns an ordinary color output;
selecting that output as a material closure is rejected before rendering.

== Image-texture preview and minification

Prepare color textures in scene-linear RGB.  A generic OSL `texture()`
lookup uses the stored numeric values; color-space conversion belongs in
asset preparation or an explicit shader operation.  Mipmapped textures
provide reduced-resolution image levels for filtered lookups.  The renderer
dependency installation supplies `maketx`:

----
mkdir -p textures
"$RENDERER_PREFIX/bin/maketx" -d float --filter box --wrap periodic \
    -o textures/wood.tx wood_linear.exr
----

An emission preview exposes texture values independently of scene lighting.
Save this shader as `texture_preview.osl`:

[source,c]
----
surface texture_preview(string in_filename = "", float in_uv_scale = 1)
{
    color texel = texture(in_filename, in_uv_scale * u, in_uv_scale * v,
        "interp", "closest");
    Ci = texel * emission();
}
----

This diagnostic uses nearest interpolation within each mip level.  Mip
selection and anisotropic filtering use the automatic OSL derivatives,
including the UV scaling operation.  Compile and select the preview:

----
"$RENDERER_PREFIX/bin/oslc" -I "$RENDERER_PREFIX/share/OSL/shaders" \
    -o shaders/texture_preview.oso texture_preview.osl
----

In MGED:

----
material create map.material "Texture preview"
material set map.material optical OSL texture_preview
material set map.material optical OSL.version 1
material set map.material optical OSL.param.in_filename "string textures/wood.tx"
material set map.material optical OSL.param.in_uv_scale "float 4"
material assign ball.r map.material
----

Then render with `art -w 512 -n 512 -o preview.png scene.g ball.r`.
Relative texture filenames resolve directly against the database directory.
They do not search the shader-library directories.  Keep textures and compiled shaders with the
database when moving the project.  Paths containing spaces are supported.

`regress-art` generates a one-texel black/white checker and converts it to
floating-point mipmapped data.  Fully minified renders of spheres,
ellipsoids, and flat and smooth authored BOTs must match an independently
shaded linear 0.5 emission reference in orthographic and perspective views.
The comparison bounds both RMS and maximum display-image error.  A control
with zero UV derivatives must differ substantially, establishing that the
check detects missing filtering.  A copied project is also rendered while
the original texture is unavailable, exercising relative asset lookup.
These checks qualify this minification workflow; LOD transitions, color
conversion, alpha, and bump/normal mapping need additional coverage.

`art` enables Appleseed's project-rooted texture lookup for both cached
constant filenames and dynamic filenames.  A same-named file in the
caller's working directory cannot override an asset or supply a missing
project texture.  Explicit absolute filenames retain their meaning.  The
regression checks these cases for 2D lookups and checks constant and dynamic
latitude-longitude environment lookups and both texture-metadata query
variants.  Missing project textures must fail unless the shader explicitly
handles the lookup error and supplies a fallback.

The environment regression also covers a modern OSL compatibility fix:
lookup directions without derivative storage supply zero footprints
instead of dereferencing absent derivatives.


== Development milestones

Each milestone requires source changes, documentation, and appropriate
regressions.  A capability is supported only after its complete user path
has passed, including installation and asset lookup where applicable.

. *Design and regression inventory.*  Maintain the responsibility contract
  and capability matrix.  Inventory the useful legacy behavior and create
  small reference scenes.  Exit when each planned feature has a known
  implementation boundary and observable acceptance test.
. *Basic OSL through librt.*  Use a simple diffuse material on a native
  Appleseed mesh, a librt sphere, a Boolean subtraction, and a BOT mesh.
  Isolate shader wiring from intersection behavior.  Exercise multiple
  regions, inherited colors, and explicit shader errors.  Exit when OSL
  shading is demonstrated on all geometry paths with automated checks.
. *Geometry and shading correctness.*  Test full database paths, repeated
  instances, transforms, material inheritance, entry/exit boundaries,
  subtraction normals, back faces, and rays originating inside solids.
  Validate offsets over different model scales.  Define UVs and their
  limitations on primitives, Boolean cut faces, and BOTs; test position-based
  mapping independently.  Validate tangent and differential behavior and
  repeated-render resource ownership.  Exit when diagnostic shaders and
  intersection tests agree with known geometry and threading is reliable.
. *Material authoring.*  Define a versioned representation for shader names,
  typed parameters, networks, connections, assets, and mapping settings.
  Integrate material objects with documented inheritance and override
  precedence.  Preserve useful existing assignments through explicit
  compatibility rules.  Provide command-based creation, inspection,
  validation, modification, saving, and reopening, with examples.  Exit when
  installed applications can reproduce the material workflow independently
  of the build tree and current working directory.
. *Core surface shading.*  Qualify diffuse and glossy reflection, metals,
  glass and absorption, transparency, emission, layering, procedural
  patterns, image textures, and bump/normal mapping.  Test secondary rays,
  nested dielectrics, cavities, thin surfaces, and transmitted shadows.
  Compare emissive surface samples with traced positions, UVs, and normals.
  Expose useful BRL-CAD attributes through renderer services.  Specify color
  spaces and distance units.  Exit when documented materials work on CSG
  and BOT geometry with semantic image checks and defined tolerances.
. *Boost removal.*  Audit declared components before replacing code.  Migrate
  containers and optional values, atomics/time, filesystem, threading, and
  specialized facilities in separate changes.  Combine rendering regressions
  with focused tests of changed path, pattern, and concurrency behavior.
  Exit when the intended renderer build has no Boost build or runtime
  dependency and its regression suite passes, including Windows behavior.
. *Rendering workflow and quality.*  Expose coherent sampling, convergence,
  bounce limits, lighting, environment, camera, and output controls.  Separate
  camera background appearance from environment illumination.  Finish
  supported light translation.  Provide diagnostic AOVs, deliberate color
  management, progress, cancellation, saveview input, framebuffer output,
  repeated frames, and scene/material inspection.  Exit when documented
  commands render representative models reproducibly with useful errors.
. *Advanced capabilities.*  Qualify subsurface scattering, participating
  media, animation/motion blur, additional shader queries, and integrators
  individually against the pinned Appleseed implementation.  Treat true
  displacement separately from bump mapping: displacing exact CSG boundaries
  needs an explicit geometry strategy.  Define overlapping-volume semantics.
  Evaluate MaterialX after the OSL network model is stable, and evaluate TBB
  and Embree through measured requirements.  Exit for each capability requires
  an implementation, examples, tests, and documented limits.  Unresolved
  capabilities remain open milestones.
. *Production qualification.*  Exercise relocatable installed builds on
  FreeBSD, Linux, Windows, and macOS.  Validate shader/compiler compatibility,
  caches, assets, cancellation, cleanup, malformed input, and large scenes.
  Record scene-preparation time, memory, intersections, shader execution, and
  thread scaling before optimizing measured bottlenecks.  Finish user and
  developer documentation and legacy migration guidance.  Exit when fresh
  installations pass the documented workflows and platform results are
  recorded; unavailable platform evidence is not a passing result.

== Validation rules

* Keep small cases with known geometric, material, and visibility answers.
  Pair appropriate cases with native Appleseed scenes to separate renderer
  behavior from the BRL-CAD adapter.
* Compile shader fixtures with the selected OSL compiler and headers.  Check
  renderer diagnostics as well as exit status; an image file alone is not
  proof of successful shader execution.
* Prefer geometric/color/energy bounds for stochastic renders.  Use exact
  pixel comparisons only for controlled deterministic cases.
* Check finite pixels, expected visible regions, material identity, image
  dimensions, output files, and error behavior.  Maintain focused lower-level
  tests for intersection, mapping, filesystem, and threading changes.
* Exercise single-worker and multi-worker rendering and multiple renders in
  one process.  Use sanitizers and resource measurements where supported.
* Preserve meaningful regressions during dependency changes.  Passing a
  narrow shader or mesh test does not establish complete CSG, material,
  installation, or platform support.
