= Rendering BRL-CAD Models with art
:doctype: article
:toc:
:toclevels: 3

`art` renders BRL-CAD databases using Appleseed for light transport and
librt for geometry intersections.  The integration is under development.
This document records the design contract, acceptance criteria, and
verified capabilities; planned capabilities are not promises of current
support.

== Application and renderer responsibilities

* BRL-CAD owns the database, Boolean geometry evaluation, instance paths,
  region and material assignments, attributes, and database units.
* `art` translates that information into an Appleseed scene and owns the
  application workflow, asset resolution, diagnostics, and image output.
* Appleseed owns light transport, sampling, OSL shader execution, closure
  interpretation, texture services, and rendering outputs.
* bext supplies the pinned dependency stack and installation machinery.

Use public renderer and OSL APIs.  BRL-CAD geometry continues to use librt;
adding native Appleseed geometry or another intersection backend must not
change the meaning of BRL-CAD Boolean evaluation.

Material translation must preserve full instance identity and resolved
inheritance.  Object, world, camera, and shader coordinate spaces and the
conversion from database units must be explicit.  Surface orientation is
geometric information: it must not be replaced with a view-dependent normal
when crossing a renderer interface.

Keep ownership explicit for prepared geometry, per-worker librt resources,
shader groups, and renderer state.  Repeated renders must release or reuse
that state deliberately, without relying on process termination.  Share
prepared geometry only where instance transforms and material assignments
remain correct.

A requested shader, parameter, or asset that cannot be used must produce an
actionable error.  Defaults apply to unspecified inputs; they must not hide
an invalid explicit material assignment.  Unsupported features must be
reported rather than silently approximated.

== Existing implementations

The 2011 liboptical implementation (`sh_osl.cpp`, `liboslrend`, and
`render_svc`) contains examples of shader parameters, networks, hit-point
inputs, reflection/refraction, and worker state.  Its private OSL interfaces
and custom closure sampling are historical implementation details, not the
interface for a modern Appleseed integration.  Recover useful semantics and
examples as public-API implementations and regression cases.

The later `art` prototype introduced Appleseed procedural objects and read
shader names from a material object's optical `OSL` property.  OSL shading
was disabled in July 2026 after black renders and replaced with native
plastic materials.  Retest the failure using the modern dependency stack;
its historical diagnosis does not establish a general OSL limitation on CSG
or procedural objects.

Do not remove legacy user-facing behavior without identifying its
replacement and documenting any migration requirements.  Share material
representation and validation where there are actual consumers; keep
renderer-specific transport and execution in the renderer.

== Current verified baseline

The modernized dependency build has been exercised with LLVM 23.1.5, OSL
1.15, OpenImageIO 3.2, and OpenEXR 3.5.  Optional LLVM/Clang libxml2 support
is disabled.  The OSL compatibility patch also accommodates LLVM builds
that have libxml2 enabled.

Appleseed's core and `art` no longer require Boost.  Fixed internal patterns,
filesystem, threading, time, atomics, and utility helpers use standard C++17.
Public Perl-style filters use PCRE2; its documented newline edge semantics
replace engine-specific Boost behavior.  Optional Appleseed Python bindings
still require Boost and are disabled in the bext renderer stack.

The sandbox and installed shader standard headers come from the selected
OSL package.  Appleseed's older copies are no longer distributed.  Custom
shaders that need Appleseed closure declarations should explicitly include
`appleseed/as_osl_extensions.h` through the installed helper namespace.

== Basic rendering

A development build with Appleseed enabled can render selected database
objects with the default OSL plastic material:

----
art -a 35 -e 25 -w 640 -n 480 -P 4 -c "set samples=64" \
    -o view.png model.g all.g
----

`set` validates every assignment before applying it.  Unknown names,
trailing numeric text, overflow, and nonfinite numbers are errors.  Samples
(`samples` or `s`) and dimensions (`width`, `height`) must be positive decimal
integers within `int` range.  Light power (`light_intensity` or `li`) accepts
zero and positive fractional values representable by the renderer's float
multiplier.  `inspect_materials` and `save_overlaps` accept `0`, `1`, or `!`
to toggle.  Perspective (`perspective` or `angle`) must satisfy
`0 <= angle < 180` degrees.  `rt_cline_radius` accepts finite numbers;
negative values retain the shared command's no-override meaning.  The shared
`save_overlaps` and `rt_cline_radius` settings are stored for command
compatibility and produce warnings: their rendering effects are not yet
implemented in art's procedural geometry.

Background (`background` or `bg`) accepts libbu color syntax, including
byte RGB triples, normalized fractional RGB triples, names, and hex colors.
Quote values containing spaces, for example `set bg="1.0 0.0 0.0"`.
`set` without assignments reports the current settings.  These rules apply
to inline `-c` commands and `-M` streams, including skipped frames.
`regress-art-settings` checks invalid-input output preservation, stored
values, aliases, color forms, frame changes, and fractional-light energy.

Region colors follow combination inheritance.  When no explicit or inherited
color is available, a matching region-ID color-table entry supplies the
fallback; an unmatched region defaults to white.  Explicit black is a valid
color and suppresses the table fallback.  Light regions use the same resolved
colors.  The region color supplies a shader's default `in_color` input when
that input exists; an explicit OSL parameter overrides it.
`regress-art-region-colors` compares table colors and inheritance with
independent emission and point-light scenes on CSG and BOT geometry under
both camera projections, including table updates, missing ranges, explicit
black, material overrides, and light-color precedence.

The default material is a modest specular coat over a diffuse base.  This
baseline does not yet translate every BRL-CAD optical shader or provide a
complete custom-material authoring interface.

The material graph connects `as_plastic.out_outColor` to
`as_closure2surface.in_input`.  A library material node that only returns
an output closure does not itself set the OSL surface result `Ci`.  A
controlled comparison with the modern stack produced black material
surfaces on both a native Appleseed mesh and its procedural sphere when
that terminal connection was absent; adding it restored shading on both.
The `art` regression now exercises the connected graph on librt CSG and
BOT geometry.  This identifies a wiring failure independently of any
remaining renderer compatibility or geometric-shading issues.

For formats converted through libicv, such as PIX and PPM, `art` reserves a
unique temporary PNG and removes it after successful or failed conversion.
The intermediate uses the renderer's 8-bit sRGB output pipeline; native
OpenEXR output retains HDR data.  Existing `<output>.tmp.png` files,
directories, and symbolic links are unrelated inputs and are left intact.
`regress-art-output` checks converted images against native PNG output,
failed destination writes, temporary-file cleanup, and repeated frames.

=== Environment illumination and visible background

`environment_color` and `environment_intensity` control the constant dome
seen by lighting, reflection, and refraction rays.  `background_color` and
`background_intensity` control the backdrop seen by camera rays.  Colors
use the same libbu syntax as `bg`; intensities are nonnegative, finite,
renderer-representable multipliers applied to linear radiance after sRGB
color conversion.  For example, illuminate a model with a neutral dome
while displaying a blue background:

----
art -c "set environment_color=white environment_intensity=0.4" \
    -c "set background_color=0/0/150 background_intensity=1" \
    -o view.png model.g subject.g
----

These controls do not change point-light power.  Set `light_intensity=0`
to render with environment illumination alone.  The visible backdrop does
not supply light or appear in reflections: use the environment controls
for those effects.

Each control defaults to `inherit`, and assigning that literal clears its
override.  Inherited colors use the legacy `background`/`bg` value, also
set by `-C` or `-W`.  Inherited environment intensity uses `-A`.  Inherited
background intensity uses one when `background_color` is explicit and
otherwise uses `-A`.  With `environment_map=inherit` and
`background_source=inherit`, all four inherited controls retain the original
combined environment and background, including the original AOV behavior.
An override among these four controls selects an independent color backdrop.
`-A` must remain finite, nonnegative, and renderer-representable; legacy
point-light scaling by `-A` is unchanged.

`set` reports overrides or `inherit`; `inspect_materials=1` also reports
resolved environment and background colors and intensities.  Overrides
persist across frames, skipped frames, and `clean`.  Reset all four to
`inherit` to restore legacy behavior.  `regress-art-environment` checks
independent backdrop and illumination changes on diffuse and mirror CSG
and BOT surfaces, an analytic radiance reference, frame persistence,
resetting, and invalid-input output preservation.

==== Image-based environments

`environment_map` selects an RGB or RGBA latitude-longitude panorama for
illumination, reflections, and refractions.  Relative paths resolve beside
the database; a same-named file in the caller's working directory cannot
replace or supply a missing map.  Explicit absolute paths retain their
meaning.  Quote filenames containing spaces.  Set `environment_map=inherit`
to return to constant illumination; `environment_color` applies to that
constant mode and is retained while a map is active.

----
art -c 'set environment_map="lighting/studio.exr"' \
    -c "set environment_intensity=1 light_intensity=0" \
    -o illuminated.exr model.g subject.g
----

Map values retain HDR radiance.  `environment_map_colorspace=linear` is the
default and expects scene-linear RGB with sRGB/Rec.709 primaries.  Use
`environment_map_colorspace=srgb` for an encoded sRGB image.  Embedded color
profiles do not select a transform automatically; convert other primaries
before use.  Alpha does not attenuate environment radiance.  Images need
nonzero dimensions and three or four channels; invalid maps fail without
replacing an existing output image.

Panorama north points along +Z.  At zero rotation, +X samples the middle of
the image, +Y samples one quarter of its width, and -X lies on the longitude
seam.  `environment_rotation` rotates the map around +Z in degrees; positive
90 degrees moves a feature from +X toward +Y.  Rotations must be finite and
are normalized to one turn.  Longitude wraps with bilinear filtering across
the seam; latitude clamps at the two poles.

`background_source` selects the camera backdrop:

* `inherit` retains the original constant-mode rules above.  With a map,
  the panorama is visible unless `background_color` has an explicit value.
* `color` always uses the resolved `background_color` and its color-mode
  intensity rules, while illumination still uses the selected environment.
* `environment` always shows the illumination environment, retaining
  `background_color` as an inactive color-mode setting.

For an environment backdrop, `background_intensity=inherit` follows
`environment_intensity`.  An explicit value supplies an independent
absolute radiance multiplier for the visible environment.  It does not
change illumination or secondary rays.  For example, retain the panorama's
reflection and lighting while displaying a black background:

----
art -c 'set environment_map="lighting/studio.exr"' \
    -c "set environment_intensity=1 background_color=black" \
    -o black-background.exr model.g subject.g
----

All map controls persist through command-stream frames and `clean`, and
inspection reports the resolved file, color space, rotation, backdrop
source, and powers.  These controls do not translate liboptical's
`envmap cloud` shader.  Exclude its registration geometry from the art
selection and provide an environment explicitly.

`regress-art-environment-map` checks cardinal directions and poles,
rotation, HDR radiance, linear and sRGB inputs, mirror reflection and
analytic diffuse illumination on CSG and BOTs, independent backdrop power,
frame persistence, rooted asset lookup, and invalid-image handling.
Native Appleseed tests check filtered sampling/evaluation consistency away
from texel centers, longitude interpolation, and zero-shift pole handling.

== Sampling and path limits

The default `sampling=uniform` traces exactly `samples` camera samples per
pixel (`s` is an alias).  The default remains 25.  To spend less work on
converged image regions, select adaptive sampling:

----
art -c "set sampling=adaptive samples=256 min_samples=16 batch_size=16 noise_threshold=0.1" \
    -o view.exr model.g all.g
----

In adaptive mode, `samples` is the maximum per-pixel budget.  `min_samples`
is an optional initial uniform pass; its default of zero skips that pass.
`batch_size` controls subsequent sample batches and defaults to 16.  The
renderer compares full and half-sample estimates within image blocks,
then refines noisy blocks until they converge or exhaust the budget.
`noise_threshold` defaults to 0.1; smaller values demand closer estimates
and generally do more work.  This is the renderer's weighted block error
threshold, not a percentage or a guaranteed bound on image error.
The accepted range is 0.0001 through 10000.

The initial pass is followed by a comparison batch when budget remains.
For example, `min_samples=6 batch_size=4` needs at least ten samples to
make its first comparison.  Batches are clipped to the budget, including
budgets that are not batch multiples.  `min_samples=samples` requests a
fixed budget.  Minimum samples must be nonnegative, batch size must be
positive, and the adaptive minimum must not exceed `samples`.  An unused
minimum may exceed the budget in uniform mode; switching to adaptive
validates the complete assignment list before changing any settings.

Path controls pass through to Appleseed's path tracer.  They default to
`inherit`, which retains the renderer's defaults:

[cols="1,1,3",options="header"]
|===
|Setting |Native default |Meaning
|`max_bounces` |8 |Overall limit, excluding the first lighting bounce
|`max_diffuse_bounces` |3 |Diffuse limit, excluding the first diffuse bounce
|`max_glossy_bounces` |8 |Number of rough reflection or transmission continuations
|`max_specular_bounces` |8 |Number of ideal reflection or refraction continuations
|`rr_min_path_length` |6 |Path length before Russian roulette may prune paths
|`next_event_estimation` |1 |Estimate lighting explicitly at surface vertices
|===

The four bounce limits accept nonnegative integers, `-1` to remove that
individual cap, or `inherit` to restore the native default.  Caps combine:
removing a specular cap does not remove the overall cap or Russian
roulette.  Native global and diffuse limits of zero retain direct
lighting; glossy and specular limits of zero disable continuations of
those types.  Two ideal refractions are needed to pass through a solid
glass slab, so `max_specular_bounces=1` blocks that transmitted view while
`max_specular_bounces=2` permits it.  Rough glass uses glossy events.
Explicit lighting and surface emission are evaluated before continuation
limits, so a zero cap need not make a surface black.

`rr_min_path_length=0` disables Russian roulette; positive values select
the minimum path length, and `inherit` restores the default.
`next_event_estimation` accepts `0`, `1`, or `inherit`.  Leave it enabled
for normal rendering; disabling it can help isolate sampled continuation
paths during shader diagnosis.  These controls do not enable participating
media, thin glass, or transport features that the geometry adapter has
not yet qualified.

`renderer_log=debug|info|warning|error` selects native renderer diagnostics;
the default is `info`.  Debug includes shader `printf` messages and native
sampling statistics and can produce substantial output.  It does not
suppress art's own errors or its separate progress reports.  Sampling,
path limits, and logging persist across saved-view frames and geometry
cleanup, and `set` without assignments reports their current values.

`regress-art-sampling` counts actual camera shader evaluations to verify
uniform budgets, adaptive early stopping, strict thresholds, initial
passes, clipped batches, frame changes, and native logging.
`regress-art-bounces` checks glossy reflection and two-interface ideal
glass on CSG and BOT geometry, including inherited and unlimited limits.

== Display exposure

`display_exposure` adjusts PNG output, images converted through libicv,
and framebuffer display in photographic stops.  The default is zero;
positive stops brighten the display and negative stops darken it.  One
stop doubles linear RGB before sRGB conversion, while minus one stop
halves it.  For example:

----
art -c "set samples=64 display_exposure=1.5" -o view.png model.g all.g
----

The transform leaves alpha unchanged and clips display RGB to its valid
range after exposure.  Finite fractional stop values are accepted;
nonfinite values and incomplete numbers are errors.  Extreme finite
values saturate safely, including channels that are exactly zero.
`display_exposure=0` restores the original display pipeline.

EXR beauty images and diagnostic passes retain their original linear HDR
radiance and geometric data.  An EXR render with `-F` therefore provides
an exposed framebuffer preview alongside the original HDR file.
Exposure does not change lighting, materials, sampling, or convergence.
For saved-view streams, it persists until changed, including across
`clean`; skipped frames still update the setting.  `set` without
assignments reports the current value.

`regress-art-exposure` compares displayed images with independently scaled
emissive materials, checks fractional and extreme stops, framebuffer
agreement and alpha preservation, and verifies unchanged EXR and AOV data.
It also covers converted formats, saved-view frames, skipped settings,
invalid values, and shader-error output preservation.

== Auxiliary image output

Auxiliary output variables (AOVs) expose geometry and lighting separately
from the beauty image.  They are disabled by default.  Select a
comma-separated list with `aovs`, or use `aovs=none` to disable them:

----
art -c "set samples=64 aovs=depth,normal,position,uv,diffuse,glossy,emission" \
    -o view.exr model.g all.g
----

This writes the beauty to `view.exr` and selected passes to files such as
`view.depth.exr` and `view.diffuse.exr`.  A PNG or BRL-CAD image output uses
the same EXR sidecars: `-o view.png` still writes `view.depth.exr`.
Saved-view frame numbers remain before the pass name, for example
`view.7.normal.exr`.  Names are case sensitive, duplicates and unknown
names are errors, and the entire `set` assignment is validated before
changing state.  Selection persists through saved-view frames and `clean`.
Skipped frames produce no images.

[cols="1,3",options="header"]
|===
|AOV |Data
|`depth` |Full-float `Z` and `A`: negative camera-space Z in database base
units (millimeters), with A=1 for a surface hit.  Misses have zero Z and A.
|`position` |Full-float world-space XYZ in RGB channels, in millimeters.
Negative coordinates and values above one remain intact.  Misses are zero.
|`normal` |World-space shading normal encoded as `0.5 * N + 0.5` in
full-float RGB.  Decode with `N = 2 * RGB - 1`; a miss is `(0.5,0.5,0.5)`.
|`uv` |Full-float U and V in R and G; B is zero.  Values are not clamped.
|`albedo` |Linear RGBA surface reflectance supplied by the shading system.
|`diffuse`, `glossy` |Linear RGBA lighting contributions, including their
respective direct and indirect components.  Glossy includes ideal
specular reflection and refraction.
|`direct_diffuse`, `indirect_diffuse` |Separate diffuse lighting components.
|`direct_glossy`, `indirect_glossy` |Separate glossy lighting components.
|`npr_shading` |Linear RGBA illustrative shading before contours, supplied
by `as_npr_shading()` closures.
|`npr_contour` |RGBA contour color and stroke coverage supplied by
`as_npr_contour()` closures.
|`emission` |Linear RGBA emission directly visible to the camera.  Emission
reached through reflection or refraction contributes to indirect lighting.
|===

Geometry passes are unfiltered diagnostic samples.  They retain the last
sample written at each pixel rather than a filtered mean; through alpha
transparency, a later primary-ray surface can replace an earlier one.
They describe the primary visibility path, not the secondary surface seen
inside a mirror or through refractive glass.  Camera-space depth is stable
when orthographic tracing moves ray origins according to scene bounds;
for perspective views it is axial Z, not Euclidean range.

Color passes use the beauty image's reconstruction filter, preserve HDR
radiance, and are stored as half-float linear EXR.  Geometry passes retain
full float precision.  These are separate EXR files; libicv's RGB image
interface does not represent their arbitrary channel layouts.  Art does
not apply display conversion to AOV data.  Use the appropriate channels
explicitly when inspecting EXR; for example, a reader may present depth's
A channel before Z.

Appleseed's NPR closures can replace the physical beauty and add ray-traced
contours based on object or material boundaries, depth differences, and
normal creases.  Their line width, color, opacity, and thresholds are shader
parameters.  Depth thresholds use database base units (millimeters).
Orthographic contours use parallel stencil rays; perspective contours use
diverging rays.  `regress-art-npr` checks both projections on equal CSG and
BOT boxes, with separate object-boundary and crease controls and analytic
alpha coverage.  Physical lighting AOVs retain the pre-NPR contributions;
they do not decompose the replaced NPR beauty.  Use the NPR passes when
inspecting that replacement.  Contour coverage and surface opacity are
separate quantities, so the contour pass is not a general transparent-layer
beauty reconstruction mask.

For built-in toon shading with object and crease outlines, assign
`as_toon` and enable its contour controls:

[source,tcl]
----
material create linework.material Linework
material set linework.material optical OSL as_toon
material set linework.material optical OSL.output out_outColor
material set linework.material optical OSL.param.in_contour_object "int 1"
material set linework.material optical OSL.param.in_contour_creases "int 1"
material set linework.material optical OSL.param.in_contour_width "float 1"
material assign model.g linework.material
----

The engineering recipes in `share/db/art` use the same contour closure
with illustrative shading and translucent envelopes.

Cancelled renders and shader errors leave existing beauty and sidecars
unchanged.  AOVs are saved before the beauty; a sidecar write failure
returns failure and leaves the existing beauty unchanged.  Writing the
set of files is not atomic: earlier sidecars can exist if a later write
fails.  Successful completion is reported only after all selected output
has been saved.

`regress-art-aovs` checks analytic depth, position, normals, and UVs on CSG
and BOTs; HDR emission; diffuse albedo; direct/indirect reconstruction;
lighting reached through two refractive interfaces; frame selection;
format-independent sidecar naming; cancellation; and output failures.

== Progress and cancellation

Art reports the frame number when rendering starts, completed tiles during
long renders, and the final tile count and elapsed time after saving the
image.  Intermediate reports appear at most once per second.  Tile
percentages count image work completed; sampling quality is controlled
separately.  Each saved-view frame starts a fresh count, including partial
edge tiles.

`set progress=0` disables these art status messages; `set progress=1`
enables them and `set progress=!` toggles the current value.  The default
is enabled.  The setting persists across saved-view frames and geometry
cleanup.  Native renderer diagnostics remain available with progress off.

Press Ctrl-C during rendering to request cancellation.  Art asks the
renderer to stop, waits for its workers and resources to finish cleanup,
and returns failure without saving the cancelled frame.  Existing output
for that frame remains unchanged.  Earlier completed frames remain
available and later frames in the stream are not rendered.  Cancellation
also works with progress disabled and with framebuffer output enabled;
the framebuffer can retain tiles already completed.

The interrupt handler belongs to one render and restores the caller's
previous handler afterward.  Geometry loading before renderer setup and
image saving after the render retain their usual process signal behavior.
The command-line interruption regression uses POSIX signals.  Native
Windows console delivery and interactive framebuffer windows still need
platform qualification.


== Framebuffer display

`-F device` displays completed tiles while rendering and can be combined
with `-o image.png` or `-o image.exr`.  The display uses the beauty image's
sRGB conversion, matching PNG output within 8-bit rounding and dithering.
HDR EXR output retains scene-linear radiance; the framebuffer clips values
outside its display range.  Alpha is omitted from framebuffer RGB pixels.

Each image uses its own framebuffer connection, including successive
frames from a saved-view stream.  Small renders request a device at least
512 pixels in each dimension and use integer zoom.  A device smaller than
the requested image is an error; it does not change the saved image size.
Open, view, tile-write, and flush failures fail the render before saving
its image.  Art saves the image before closing the device, so a lingering
window does not delay the saved file.  A close failure returns an error,
but the image can already have been saved.  A framebuffer can also contain
completed tiles when a later error occurs.


== Camera pose

`art` accepts rt camera commands either through separate `-c` options or
as a semicolon-terminated `-M` command stream.  A complete explicit pose
supplies a positive `viewsize`, an `eye_pt` in database model coordinates,
and either an `orientation` quaternion, a `viewrot` matrix, or a
`lookat_pt`.  Quaternions use BRL-CAD's `(x, y, z, w)` convention.
For example, an orthographic view down the negative Z axis is:

----
art -p 0 -w 640 -n 480 -P 4 \
    -c "viewsize 80" -c "eye_pt 0 0 60" \
    -c "orientation 0 0 0 1" -o view.png model.g all.g
----

The equivalent pose can appear between `start 0;` and `end;` in an
`-M` stream.  Supplied camera fields survive scene preparation; the
azimuth/elevation defaults no longer replace an explicit pose.  A zero
perspective angle selects the orthographic camera, which is also the default
as in rt.  The prototype's earlier default can be requested with `-p 85`.
Positive angles below 180 degrees select a pinhole camera and specify its
horizontal field of view.  Orthographic film width equals `viewsize`, and image dimensions
supply the film aspect ratio.  An explicit perspective eye controls its
distance independently of `viewsize`.

The renderer receives an affine camera pose.  BRL-CAD's homogeneous view
scale is expressed through film dimensions instead of a projective camera
transform.  Before rendering, `art` rejects nonfinite camera state, singular
orientations, and invalid view sizes or fields of view without replacing an
existing output.  The shared rt parsers retain their legacy warnings and
coercions; strict validation of every command and option spelling remains
open.
`regress-art-view` compares command-stream and command-line poses with
independent azimuth/elevation views on asymmetric geometry.  It covers
both projections, quaternion handedness, matrix and look-at commands,
perspective eye distance, and a known two-axis orthographic image shift.

=== Saved views and cleanup

In mged, `saveview -e art -o view.png view.sh` creates a rendering script
using the current view and displayed objects.  Execute that script with a
shell and add art's pixel dimensions and worker count as arguments.  Keep
`art` on `PATH` when executing the script.  An orthographic saved view needs no perspective override; a perspective saved
view includes its field of view.

Use `opt -o "image name.png";` in a command stream to change the output
path for subsequent renders.  Output paths remain valid after the option
command finishes, including quoted names containing spaces.

The generated `-M` command stream contains `clean` before rendering.  `art`
releases each render's project and procedural objects when the render ends;
`clean` discards the prepared librt geometry, which is loaded and prepared
again for the next render.  Camera commands survive this cleanup.  The
original `prep` command remains available for object lists built with
`draw`.  Both command-line selections and retained command object lists
are covered by cleanup regressions.

`art-installed-view` generates the saved view through installed mged,
compares the rendered result with an independent camera setup, and executes
the complete generated shell script on Unix.  It also checks two clean/render
cycles within one art process. Active tree-list edits have their own
selection regression described below.

=== Active object selection

In `-M` input, `tree object ...` replaces the active tree tops, `draw object
...` adds tree tops without duplicating an existing name, and `erase object
...` removes named tree tops. Each command accepts multiple objects. The
initial selection comes from the command line or `-I` object file; a stream
may also establish its selection without either. Geometry preparation and
material traversal use the same active list. Removing every object reports
an empty-selection error when rendering, without falling back to the original
command-line objects.

Selection edits invalidate prepared geometry automatically. `prep` loads the
current selection explicitly, and `end` prepares it as needed. `anim` also
invalidates geometry so articulation changes reach subsequent renders.
Selection edits retain animation commands; an explicit `clean` clears
articulation while retaining the selected object names. Failed tree loading
stops the stream. Selection commands require an open database and belong in
`-M` input, rather than command-line `-c` options processed before database
loading. Frame, preparation, and cleanup commands also require database
loading. Failed `-c` commands return an error. `multiview` and the internal
`_closedb` debugging command are unsupported and report errors; use explicit
`start`/`end` blocks for multiple views.

`regress-art-selection` compares multi-object edits, replacements, repeated
frames, and retained/reset articulation with independent reference renders.
It checks empty selections, missing objects, and inline-command errors while
preserving existing output files. The same test runs against installed art.
The shared command handlers also have a native `rt_command_selection`
regression with deterministic pixel comparisons.

Air regions are excluded consistently with librt's default tracing policy.
The scene and material walk skips every nonzero air code before resolving a
material or constructing a renderer object.  Inspection reports these paths
as `air_region ... skipped`.  Selecting an assembly containing air therefore
does not make excluded regions fail object loading or material validation.
`-U` remains unsupported; this exclusion does not provide participating media.
The selection regression checks direct and transformed nested air regions
with different air codes and deliberately invalid material assignments.

=== Command-stream frames

A `start N; ...; end;` block renders frame _N_.  Frame zero uses the requested
output path unchanged.  Positive frame numbers are inserted before the file
extension: `-o shot.png` writes `shot.1.png` for frame one.  This preserves
PNG, EXR, and BRL-CAD image-format selection.  A later `opt -o` command sets
a new base path for subsequent frames; generated frame names do not alter
that base path.  A stream without a `start` command renders the implicit
frame zero used by older command streams.

`-D first -K last` selects an inclusive frame range in `-M` mode.  Setup
commands in frames before _first_ still execute, retaining camera, object,
and animation state needed by selected frames; their `end` commands skip
rendering.  The first `start` beyond _last_ ends processing successfully.
Reaching the end of a stream before any selected frame is also successful
and writes no image.  `-K -1` means there is no upper limit.

Frame numbers must be nonnegative decimal integers.  Invalid ranges,
malformed frame numbers, a second `start` before `end`, and an unfinished
frame at end of input produce an error.  `regress-art-frames` checks distinct
numbered images, inherited state across skipped frames, range completion,
quoted output paths, PNG/PIX/EXR writers, and invalid streams.  The same
regression runs against installed applications.

== Geometry boundary handling

The procedural callback receives the original geometric hit normal in object
space.  Appleseed retains that normal, the shading normal, UVs, and material
slot as intersection inputs, so copies and side changes can reconstruct
shading consistently.  The callback returns a normal facing the incoming ray
and offsets on both sides of that surface.

`art` scales its normal displacement by floating-point precision, hit-point
coordinates, prepared object extent, and incoming ray travel.  The last term
accounts for cancellation when reconstructing a nearby surface from a
distant ray origin.  It rounds each displaced coordinate
away from the surface, following the directed-rounding approach described in
https://www.pbr-book.org/4ed/Shapes/Managing_Rounding_Error[Managing Rounding Error].
Rendering queries opt out of librt's near-origin zero snapping to preserve
the sign of entry boundaries behind an inside ray.  Boolean coalescing and
model tolerances still apply.  Positive exits close to the origin remain
visible.  The regression checks normal orientation and traces reflected and
transmitted rays to detect self-hits and skipped boundaries.  Formal error bounds from
each librt primitive and qualification near the representable feature-size
limit remain open; the rounding allowance does not establish those bounds.

The Appleseed procedural callback signature has changed.  Rebuild applications
and procedural plugins against the matching renderer headers and library.

== Geometric and shading normals

`art` passes separate normals to Appleseed.  The geometric normal describes
the actual boundary and controls surface sides and secondary-ray offsets.
Authored BOT vertex normals interpolate the shading direction independently;
a smooth appearance does not change the intersected geometry.  Both normals
receive the Boolean partition's flip when a primitive supplies a cut face.

The public librt `rt_obj_normals` query reads the original intersection
without changing it.  BOT and DSP provide separate geometric and shading
normals; other primitives use their existing normal method for both outputs.
The query rejects nonfinite or zero normals and orients the shading normal
into the geometric normal's hemisphere.  It preserves authored interpolation
without the legacy BOT/DSP clamping to the incident ray.  Existing normal
queries retain their historical behavior.

Exact tests cover smooth BOT entry and exit, nonuniform transforms, Boolean
subtraction, clockwise winding, and grazing/back-face queries.  An OSL
emission diagnostic renders the difference between `N` and `Ng` on a smooth
BOT, checking that the distinction reaches shader execution.  The same
diagnostic on a flat BOT checks that the normals agree.  DSP ray tests
also exercise repeatable queries and view-independent shading directions.
These checks do not yet qualify bump mapping, normal maps, or all light
transport cases at shading discontinuities.

The librt function table has a new optional normals callback.  Rebuild
consumers against the matching librt headers and library.

== Transmission and absorption

A region's material is assigned to both its entry and exit faces.  This
allows a shader to run when looking out of a solid and at the exit boundary
of a transmitted path.  Surface sides and medium transitions still follow
the geometric normal; assigning both faces does not make every surface a
thin sheet.

For an initial glass material, select `as_glass` and its closure output:

----
material create glass.material Glass
material set glass.material optical OSL as_glass
material set glass.material optical OSL.output out_outColor
material set glass.material optical OSL.param.in_ior "float 1.5"
material set glass.material optical OSL.param.in_roughness "float 0"
material set glass.material optical OSL.param.in_transmittance_amount "float 1"
material set glass.material optical OSL.param.in_surface_transmittance "color 1 1 1"
material set glass.material optical OSL.param.in_volume_transmittance "color 0.25 0.5 0.8"
material set glass.material optical OSL.param.in_volume_transmittance_distance "float 20"
material assign ball.r glass.material
----

Volume transmittance specifies the surviving linear RGB fraction over the
given distance.  A path of length `d` has attenuation `T^(d/D)`, per channel,
for transmittance `T` and positive reference distance `D`.  A zero reference
distance disables volume absorption.  Distances use the common-space units
of the geometry passed to the renderer; material parameters receive no
implicit distance conversion.

A zero `in_roughness` selects ideal specular reflection and refraction.
The renderer uses the smooth limit directly, with Fresnel branch sampling,
surface tint, and the corresponding ray differentials.  Positive roughness
uses GGX and retains its minimum microfacet width.  Native tests check
smooth Snell directions, unpolarized Fresnel weights, tinted branch
sampling, total internal reflection, and both sides of an interface.
GGX sampling also handles exact back-face normal incidence without a
singular tangent basis.

Glass applies the squared index-ratio correction for radiance at refractive
boundaries and uses its adjoint form for importance transport.  These
factors cancel on complete air-to-air paths and remain observable for a
camera inside a dielectric.  The analytic references include this optical
measure, following
https://pbr-book.org/4ed/Reflection_Models/Dielectric_BSDF[Dielectric BSDF].

When the inside and outside indices match, the glass BSDF transmits straight
through, including for rough surfaces.  Appleseed samples this as a specular
delta event because the microfacet transmission density is singular at
matching indices.  The modern OSL integration also preserves explicit
function signatures for native closure prepare/setup callbacks; opaque LLVM
pointer values alone do not provide those signatures.

Secondary procedural intersections preserve the hit point from the actual
offset ray.  Reconstructing it from the original, unshifted origin can put
an exit point inside the solid, causing repeated self-intersections and dark
artifacts.  The renderer preserves the actual point through copies and side
changes and uses it when computing subsequent offsets.

`regress-art-transmission` isolates absorption by matching the glass index
to the environment's index of one.  It compares rendered attenuation with
independent analytic solid path lengths under a constant environment, for
orthographic and perspective views.  The cases cover CSG cubes, spheres,
ellipsoids, a box with a cylindrical bore, and flat and smooth solid BOTs.
A disabled-absorption control must match the environment and disagree with
the absorbing reference.  Inside-camera emission checks cover exit-face
material assignment.  A native transformed-slab test checks actual secondary
hit positions, copying, side changes, and escape without another hit.

The transmission regression's index-1.5 render compares geometrically
identical CSG and BOT cubes under a constant environment.  The separate
`regress-art-refraction` provides an independent reference: it analytically
traces two smooth interfaces and their Fresnel weights to a finite emissive
receiver whose color encodes position.  It includes the receiver's side
faces and rays that miss its bounds.  Reflection tint is zero to isolate
the directly transmitted paths.  CSG cubes, flat BOT cubes, spheres, and
ellipsoids are checked at indices 1.5 and 2, in orthographic and perspective
views at elevations 90 and 65.  A neutral-background emission control proves
that each view contains the tested solid.  A straight-through reference
must fail the refracted-path comparison.

Native tests compare reflected and transmitted neighboring directions with
independent analytic rays on a plane and sphere.  Glass passes the refractive
ratio, rather than roughness, to its transmitted-differential calculation.
These checks establish the tested first-order direction changes; filtered
textures along secondary paths still need image-based qualification.

General rough-glass transport, multiple internal bounces, caustics,
transmitted shadows, general overlapping media, thin surfaces, and
bump/normal-mapped transmission need further qualification before a general
production-glass claim.  The distinct-priority nested-volume case below
has independent image references.

=== Nested optical volumes

`OSL.medium_priority` assigns Appleseed's medium priority to each region
instance using a material.  It is material metadata, separate from shader
inputs.  For example:

[source,tcl]
----
material set glass.material optical OSL.medium_priority 1
material set liquid.material optical OSL.medium_priority 2
material set bubble.material optical OSL.medium_priority 3
----

The value is a bare integer from -128 through 127 and defaults to zero.
Higher priorities select the active medium where optical volumes overlap;
a lower-priority contained region is displaced by its surrounding medium.
Use distinct increasing priorities for successively nested media.
Equal priorities do not establish the required ordering for nested indices
and absorption.  Negative priorities are supported.  Material inheritance
and child overrides follow the normal OSL definition rules; replacing a
root shader resets the inherited definition, including priority.
`inspect_materials=1` reports the effective priority before rendering.
Invalid priorities fail without replacing an existing image.

Native priority filtering can currently skip an enclosed opaque BSDF whose
priority is lower than the surrounding glass.  Assign such opaque parts a
higher priority while that filtering is being corrected.  This limitation
also affects materials combining emission with a diffuse or glossy BSDF.

The qualified representation uses full, deliberately overlapping closed
volumes: the outer volume contains the complete inner volume, and an
optional higher-priority air-like core can be placed inside it.  The
priority controls which volume supplies the index and absorption on each
path segment.  This does not qualify coincident interfaces between a CSG
shell and a separately modeled filling.  Those shared boundaries require
separate handling.  Optical air-like regions in this workflow remain
ordinary regions with an index of one; BRL-CAD air regions continue to be
excluded from art rendering.

`regress-art-nested` compares two- and three-layer CSG and solid BOT boxes
with a separate shader that traces their interfaces analytically.  It
checks Snell directions, Fresnel transmission, and colored Beer absorption
at each segment, including different indices, orthographic and perspective
views, oblique rays, negative priorities, inherited settings, and hidden
lower-priority regions.  Reflection tint is zero to isolate directly
transmitted paths.  The reference checks its slab-face bounds explicitly;
these tests do not establish rough, multiply reflected, or arbitrary
interpenetrating-volume transport.  A tied-priority control must fail the
physical nested-absorption comparison.

`regress-art-absorption` checks energy arriving at an emitter inside one
or two absorbing volumes.  Equal-index CSG and BOT paths agree with
independent segment-wise Beer attenuation, including terminal bounce
limits and indirect glossy diagnostic passes.  Both orthographic and
perspective center rays are checked; disabling absorption recovers the
emitter's full HDR radiance.

Art initializes optical media at each primary ray's actual origin.  It
identifies containing, consistently oriented closed volumes before shading
any surface, evaluates their glass interiors, and orders them by medium
priority.  This applies absorption even when the first visible surface is
an emitter inside the glass.  Index-one absorbing glass is still an optical
medium; opaque, emissive, and illustrative materials do not acquire a glass
interior merely because the ray starts inside their geometry.

The native medium list holds eight volumes.  Discovering more containing
optical volumes fails without replacing an existing image.  Touching or
coincident boundaries, open surfaces, and plate-mode representations are
outside this qualification.  Use distinct priorities and homogeneous glass
interiors for the qualified nested workflow.

A pinhole ray starts at the camera's eye point.  Appleseed places an
orthographic ray a scene diameter behind its nominal eye point, so moving
that eye inside a solid need not put the ray origin inside it.
`regress-art-initial-media` compares pinhole views starting in outer glass,
inner liquid, and an air-like core with analytic Snell, Fresnel, and Beer
references, and retains orthographic views as outside-origin controls.
It covers CSG and solid BOTs, oblique views, equal and distinct indices,
internal emission, unrelated foreground geometry, and capacity failures.

The renderer's BSDF interface now reports whether evaluated inputs define
an optical interior.  Rebuild plug-ins that subclass that interface.

=== Plate-mode BOTs

Plate mode constructs entry and exit distances around each ray's crossing
of a triangle.  Straight transmission through centered plates agrees with
analytic Beer attenuation.  Refraction can bend a ray past the face that
would supply its exit, producing edge artifacts.  The raw plate-mode
representation is not qualified as a refractive volume.

Author an explicit physical volume before assigning refractive glass.  In a
copy of the database, this command replaces the plate primitive while
preserving references from its regions and combinations:

[source,tcl]
----
bot extrude --max-area-delta 0 -i windscreen.bot
----

The zero area-change setting disables simplification.  This workflow is
qualified for centered `plate` mode; appended thickness and `plate_nocos`
require separate geometry decisions.  Conversion is an explicit authoring
operation because a closed volume has different edge boundaries from the
shotline-based plate representation.  art continues to trace the authored
BRL-CAD geometry with librt.

`rt_bot_plate_volume` checks dimensions, volume, manifoldness, and input
preservation at three scales and translated coordinates.  Coplanar faces
with consistent or reversed winding retain their planar outline; actual
bends retain the rounded join.  The conversion's coplanarity adjustment is
fractional, avoiding a fixed millimeter displacement of small plates.
`art-installed-plate` uses installed mged to create and convert a plate,
then compares raw and converted equal-index absorption and converted-volume
refraction with independent references.  Its 20 image comparisons cover
both projections, both sides for absorption, two view angles for refraction,
and indices 1.5 and 2.  A wrong-index control must fail.  The fixture retains
FASTGEN `P` region metadata while replacing its primitive in place;
inter-region FASTGEN overlaps remain unqualified.  Conversion creates new
topology and does not preserve authored BOT normals or UVs.  These renders
use uniform glass and facet normals.  The Generic_Twin demonstration additionally
checks its actual converted windscreen for closure and manifoldness and
compares equal-index transmission with an unobstructed target.  An opaque
control distinguishes transmission through its authored index-1.5 glass.
This qualifies that specific uniform-glass workflow; general curved plates,
variable thickness, and rough glass remain unqualified.

== Surface coordinates

OSL `u` and `v` come from the intersected librt primitive's native mapping.
Boolean cut faces retain the mapping of the primitive that supplied the
boundary.  Sphere and cylindrical mappings have seams, and ARB faces have
independent planar coordinates; a Boolean operation does not create a new
continuous parameterization.

BOT meshes with authored texture coordinates interpolate the per-corner
coordinates of the intersected triangle.  Separate texture indices preserve
seams.  Coordinates outside the unit square remain available for tiling.
Database transforms move the geometry without changing its authored UVs.
A BOT without authored UVs, or a primitive without a supplied mapping,
returns `(0,0)`; `art` does not generate a projection in that case.

The diagnostic emission shader in `regress-art` renders `(u,v,0)` on a
sphere, a Boolean solid, and a BOT without depending on illumination.
Exact intersection tests check coordinates and transformed instances;
`rt_bot_uv` also checks packet intersections, winding, degenerate faces,
malformed data, and ownership of prepared coordinates.  `rt_arb_uv` exercises
concurrent first-use mapping and normal queries.

These checks establish point coordinates.  Appleseed now accepts optional
object-space derivatives of position and the unit shading normal with
respect to UV.  It preserves them through copied hits and side changes,
transforms position derivatives as vectors, and differentiates both the
inverse-transpose normal transform and normalization.  Ray footprints use
the geometric surface and a double-precision UV solve.  Native renderer
tests compare normal derivatives to finite differences and check known UV
footprints, including very small and large scales with analytic inverses.
Native sphere, rectangle, and disk intersections supply their analytic
mapping derivatives; singular mappings report unavailable derivatives.

`art` fills these inputs from native librt mappings for authored BOT UVs,
spheres, and ellipsoids.  Boolean cuts reverse normal derivatives while
preserving position derivatives and UVs.  Missing or singular mappings
produce zero UV footprints, with an independent shading basis fallback,
rather than an arbitrary mapping scale.  Other primitives currently supply
point UVs only where available.

The analytic callbacks preserve the prepared UV frame, including axes
accepted within preparation tolerances.  Finite-difference tests cover
position and unit-normal derivatives, rotated frames, inside rays, and
singular poles.  Art intersection tests check the transferred derivatives
against known chart tangents and independent nearby-ray normal differences.
An OSL emission diagnostic evaluates `filterwidth(u)` and `filterwidth(v)`
in actual orthographic and perspective renders.  Spheres, ellipsoids, and
flat and smooth authored BOTs must produce finite, positive footprints.
The current ARB/TGC Boolean fixture must produce the zero-footprint fallback.
These checks establish that the mapping derivatives reach OSL.  Mipmapped
texture minification is also checked against a known reference as described
below.  Native bump gradients and normal-map network behavior are checked
separately, including chart orientation and mirrored UVs.
Rebuild procedural
plugins and applications against the matching Appleseed headers and library.

Visible emission is covered by the diagnostic shader, but direct light
sampling of emissive librt surfaces and their surface-area registration are
not implemented.  Emission visibility does not establish an efficient area
light workflow or area-normalized power controls.

== Selecting an OSL material

The existing `material` command can select a compiled OSL shader for a
region.  For example, in MGED:

----
material create paint.material Paint
material set paint.material optical OSL as_plastic
material set paint.material optical OSL.output out_outColor
material assign ball.r paint.material
material get paint.material optical OSL
----

The optical `OSL` property names the shader.  For a library shader node,
`OSL.output` selects a scalar closure-color output and defaults to
`out_outColor`.  `art` connects it to `as_closure2surface`.  A shader declared
as `surface` writes `Ci` itself and must not specify `OSL.output`.

Shaders are queried through Appleseed's public metadata interface before
rendering.  Missing shaders, invalid outputs, and invalid material-object
references stop the render with an error.  The region's resolved sRGB color
is converted to linear RGB and supplied to a compatible scalar `in_color`
input, when present.  Explicit typed parameters override this color and the
compatibility defaults for `as_plastic`.

Version 1 stores typed inputs in optical properties named
`OSL.param.<input>`.  `OSL.version` can be set to `1`; omitting it retains
version 1 behavior for existing assignments.  For example:

----
material set paint.material optical OSL.version 1
material set paint.material optical OSL.param.in_color "color 0.2 0.4 0.6"
material set paint.material optical OSL.param.in_specular_roughness "float 0.35"
material get paint.material optical OSL.param.in_specular_roughness
material remove paint.material optical OSL.param.in_specular_roughness
----

Supported input types are `int`, `float`, `color`, `point`, `vector`,
`normal`, `matrix`, and `string`.  A value starts with its exact OSL type.
Triples require three components; matrices require sixteen components in
the renderer's row-major order.  Numeric components must be finite and
representable in the renderer's `int` or `float` storage.  Explicit colors
are linear RGB.  Points, vectors, and normals use the shader's common
coordinate space; no implicit unit or coordinate conversion is applied.
A string contains the remaining text after `string`, including internal
spaces; leading and trailing whitespace is trimmed.  Tcl quotes group the
property value and are not part of the stored string.

OSL inputs declared with `lockgeom=0` can read per-hit renderer data.
Literal parameters are fallback defaults on those inputs; shader
connections override the per-hit binding.  For example, overriding the
normal-map `Tn` or `Bn` frame requires a vector-output connection.

Unknown inputs, type mismatches, invalid values, output assignments,
closures, structures, and arrays stop rendering before an image is written.
Unknown `OSL.` properties and unsupported format versions also produce an
error.  Unspecified inputs retain the shader or compatibility defaults;
removing an input property restores those defaults.  The regression uses
the material command to persist and reopen every supported input type,
including a string with spaces, before checking rendered shader results.

Version 2 adds shader networks.  The `OSL` shader is still the terminal
material layer, named `material`, and retains its version 1 parameters,
color defaults, and output rules.  Declare utility nodes with
`OSL.node.<layer>` and set their inputs with `OSL.param.<layer>.<input>`.
A property `OSL.connect.<destination-layer>.<input>` names its source as
`<source-layer>.<output>`.  For example, this network feeds a utility color
through a native Appleseed plastic shader:

----
material set paint.material optical OSL.version 2
material set paint.material optical OSL.node.tint as_blend_color
material set paint.material optical OSL.param.tint.in_color "color 0.2 0.4 0.6"
material set paint.material optical OSL.param.tint.in_color2 "color 0.5 0.5 0.5"
material set paint.material optical OSL.param.tint.in_blend_mode "string Multiply"
material set paint.material optical OSL.connect.material.in_color tint.out_color
----

Layer names and connection endpoint names use ASCII letters, digits, and
underscores, starting with a letter or underscore.  `material` and `surface`
are reserved layer names.  Nodes are ordered by their dependencies;
attribute order and lexical layer order do not control execution.  A
connection overrides an explicit literal or default on the connected input.
Only the terminal material receives the region-color and plastic
compatibility defaults; utility nodes retain their shader defaults.

Connections require a declared output and input of the same OSL type;
closure-color connections are supported.  Whole arrays can connect when
their element types and fixed lengths match.  Unsized arrays, structures,
component connections, and implicit type conversions are unsupported.
Only the terminal shader can be declared `surface`.  Missing nodes or endpoints,
invalid node parameters, cycles, and nodes that do not contribute to the
terminal material are errors.  Version 1 continues to reject network
properties.  The regression persists and reopens multi-node numeric and
closure networks and compares them with equivalent single-node materials
on spheres, ellipsoids, Boolean geometry, and flat and smooth BOTs.

=== Material assignments along instance paths

A combination's material reference applies to regions reached through it.
With `inherit` unset or zero, a lower combination or the region can supply
an overriding reference.  Setting `inherit` to one on a combination with
a material reference locks that assignment for the remainder of the path.
For example, given an existing material and region:

[source,tcl]
----
g painted.g ball.r
material assign painted.g paint.material
attr set painted.g inherit 1
----

Rendering `painted.g` uses `paint.material` even if `ball.r` has its own
material reference.  Setting `painted.g`'s `inherit` to zero lets the
region's reference take precedence.  If the region has no reference, it
still receives the parent's assignment.  An empty reference does not clear
an ancestor assignment or lock inheritance.  If the full path has no
assignment, the default OSL plastic uses the resolved region color.
Color inheritance remains independent of named-material inheritance.

Separate parent combinations can assign different materials to occurrences
of the same region.  Repeated arcs under one combination share that
combination's assignment; wrap occurrences in separate combinations when
they need different materials.  These rules select the region's material;
they do not assign materials to individual Boolean faces or solids below
the region boundary.  Legacy `light` region conversion is a separate path.

Resolution starts at the first object in the selected path.  Selecting
`ball.r` directly does not include assignments from parents elsewhere in
the database.  Selecting a full path such as `/painted.g/ball.r` includes
that parent and its assignment.  Only the effective reference is loaded
and validated: an overridden reference or one suppressed by a locked
ancestor does not cause an error.  The selected material's complete parent
chain must be valid, as described below.

The material regression checks lower overrides, ancestor locks, missing
references, empty assignments, repeated arcs, and selection of a region,
parent, or full path under both camera projections.  It also moves a project
containing inherited networks and custom shaders to a new directory and
renders from a separate working directory.

=== Material parents

A material object's `parent` names another material object in the same
database.  Omit `OSL` on a child to inherit its parent's shader definition;
local optical properties override matching inherited keys.  For example:

[source,tcl]
----
material create base.material Base
material set base.material optical OSL as_plastic
material set base.material optical OSL.param.in_specular_roughness "float 0.35"
material create blue.material Blue
material set blue.material parent base.material
material set blue.material optical OSL.param.in_color "color 0.1 0.3 0.7"
material assign ball.r blue.material
----

Version 2 node declarations, parameters, and connections can be inherited
and overridden by key.  An explicit `OSL` property starts a fresh definition,
including when it repeats the parent's shader name.  Its own parameters and
network replace the inherited OSL definition, which prevents stale inputs
or connections from an earlier shader from leaking into the replacement.
Removing a local override exposes the inherited value again.

Resolution follows the complete parent chain and reports missing parents,
non-material objects, and cycles.  Invalid parent links are errors even
when a child declares a replacement shader.  Errors stop rendering before
an existing output is replaced.  Parent chains are resolved iteratively;
they do not themselves add shader or coat layers.

These rules apply to `art`'s OSL definitions.  `material get` reports the
properties stored on the named object.  `regress-art-materials` persists
and reopens inherited single-shader and network definitions on CSG cubes,
flat BOTs, spheres, and ellipsoids under both projections, including a
32-link chain and error-output preservation.

Errors reported by the renderer during initialization, worker execution,
or renderer cleanup stop the render with a nonzero exit status before
saving an image or replacing an existing output.  This includes unhandled
OSL texture errors, even when
Appleseed's render status otherwise reports success.  Warnings alone do
not fail the render.  A shader may deliberately request the `texture()`
`errormessage` output and supply its own fallback; handled errors that do
not reach the renderer error log remain under the shader's control.
`regress-art` checks both missing-texture behaviors.


=== Inspecting resolved materials

Inspect the selected region instances before committing to a render:

----
art -c "set inspect_materials=1" model.g all.g > materials.txt
----

The report goes to standard output; diagnostics go to standard error.
It records the project directory and shader search path, then identifies
each region by its full indexed instance path.  Each material record gives
the selected assignment and source path, whether that assignment locks
inheritance, the material-parent chain from child to oldest parent, shader
layers, typed input bindings, connections, and the terminal surface result.
Legacy light regions are identified separately as point lights.

Input bindings include the resolved region color, plastic compatibility
defaults, and inherited and local parameter assignments.  Inputs supplied
by a connection mark their literal binding as overridden.  Inputs not
listed retain their shader defaults.  For example, part of an inherited
plastic network report could read:

----
region "/painted.g/ball.r"
  assignment "paint.material" from "/painted.g" inherit higher
  material_chain "paint.material" "base.material"
  shader "tint" "as_blend_color" shader
  shader "material" "as_plastic" shader
  connect "tint.out_color" -> "material.in_color"
  connect "material.out_outColor" -> "surface.in_input"
  shader "surface" "as_closure2surface" surface
  result "surface.Ci"
----

Inspection uses the same assignment, inheritance, parameter, connection,
and shader-interface validation as rendering.  A bad selected material or
object path exits with an error and publishes no partial report, including
when an earlier region was valid.  A selection with no regions is an error.
No image or framebuffer is opened, even if `-o` or `-F` is present.  Geometry
preparation is skipped, so material inspection also works on empty regions.
The stdin `end` command uses the same inspection path when this mode is set.

This is static material validation.  Shaders are not executed and texture
files are not opened; a valid report cannot establish that a texture exists
or that a closure works during rendering.  The report retains authored
string values, including asset filenames, and quotes embedded quotes and
backslashes.  Run a render to validate texture loading and shader execution.

`regress-art-inspect` checks assignment sources and parent chains, inherited
network parameters, overridden literals, closure adapters and direct `Ci`
shaders, quoted string values, empty regions, light classification, invalid
paths and graphs, output preservation, and stdin inspection.  A moved
project with a conflicting shader in the caller's working directory must
still resolve its own shader interface.

== Native image-node failures

A native `as_texture` node reports a missing named file or failed lookup as
an OSL error by default.  `art` then exits without creating or replacing an
image.  An unassigned filename uses the node's fill defaults.

To deliberately render a fill when a named texture is unavailable, set
`OSL.param.<node>.in_error_on_missing` to `int 0`.  The node then supplies
`in_color`, `in_alpha`, and the raw RGB mean of `in_color` on `out_channel`.
Fill values are used directly.  The regression checks the color and both
scalar outputs, an empty filename, and preservation of an existing render
when the requested image is missing.


== Reflection mixtures

Zero-roughness glossy and metal BSDFs sample ideal reflection.  Their
continuous evaluation and PDF return zero, matching that discrete sampling
contract.  Evaluating a narrow finite lobe instead can add spurious energy
through next-event estimation.  Native tests cover both entry points, and
the mapped-environment regression checks absolute reflected radiance.
This preserves the sharp reflection described by the
https://open-shading-language.readthedocs.io/en/stable/stdlib.html[OSL closure reference].

Version 2 networks can blend closure outputs with `as_blend_shader`.  Its
terminal output is `out_color`.  Connect the two material closures to
`material.in_color` and `material.in_color1`, enable the second layer with
`OSL.param.in_layer_visibility1` set to `int 1`, and set
`OSL.param.in_weight1` to a float between zero and one.  With the first
layer's default weight of one, the result is `(1-weight1)*first +
weight1*second`.  This is a weighted mixture; a physically coated material
requires its own transport model and qualification.

`regress-art-mixture` uses two half-reflecting ideal mirrors with different
shading normals under a constant environment of radiance 0.4.  Every mixture
must return radiance 0.2, independently of the selected closure.  Five
weights, including both endpoints, are compared with an emission reference
on CSG cubes, flat BOT cubes, spheres, and ellipsoids in orthographic and
perspective views.  Both a single surface shader and a persisted network
using the native blend node are checked.  An intentionally darker material
must fail the same comparison.

The Appleseed adapter compensates delta samples for closure selection,
retains eligible closures after mode filtering, and evaluates each continuous
closure in its own shading frame.  Native tests independently check mixed
diffuse/mirror throughput, cosine-weighted diffuse mixture densities and
values, mode masks, and the supported closure-count limit.  These checks do
not qualify arbitrary layered materials, denoising albedo, or nested media.

== Plastic and metal surfaces

For a colored plastic with a white specular response, set the library
shader's inputs explicitly:

[source,tcl]
----
material create paint.material Paint
material set paint.material optical OSL as_plastic
material set paint.material optical OSL.output out_outColor
material set paint.material optical OSL.param.in_color "color 0.3 0.5 0.7"
material set paint.material optical OSL.param.in_specular_color "color 1 1 1"
material set paint.material optical OSL.param.in_specular_weight "float 1"
material set paint.material optical OSL.param.in_diffuse_weight "float 1"
material set paint.material optical OSL.param.in_specular_roughness "float 0.35"
material set paint.material optical OSL.param.in_ior "float 1.5"
material set paint.material optical OSL.param.in_scattering "float 1"
material assign ball.r paint.material
----

Color inputs are scene-linear.  `in_scattering` controls the existing
plastic model's internal diffuse correction; the example explicitly uses
its nonlinear form.  This parameter does not enable participating media.
An explicit roughness of zero selects ideal specular reflection over the
diffuse base.  Positive roughness retains GGX's finite minimum width.

Appleseed selects plastic's diffuse and specular lobes using the outgoing
surface Fresnel estimate, independently of the sampled microfacet normal.
Continuous samples return the complete enabled response and its marginal
sampling density.  Ideal specular samples include their lobe-selection
compensation and cosine normalization.  Native tests check mode restrictions,
smooth reflection, sampled/evaluated agreement, and independent numerical
hemisphere integrals for rough plastic.  These changes correct sampling;
the existing finite-roughness BRDF evaluation model is retained.

For an isotropic metal, select `as_metal` and set
`OSL.param.in_face_reflectance`, `OSL.param.in_roughness`, and
`OSL.param.in_energy_compensation`.  Face reflectance is a scene-linear
color, roughness is a float, and energy compensation defaults to one.
The independent direct-light comparisons disable compensation to isolate
Schlick conductor Fresnel and GGX masking.  A separate white-furnace test
checks that compensated white metal returns the constant incident radiance;
an uncompensated rough-metal control must disagree.

`regress-art-surface` compares three finite roughnesses with independent
point-light references on CSG cubes, flat BOT cubes, spheres, and ellipsoids
under both projections.  Rough plastic at normal incidence also uses a
numerical hemisphere reference and a one-percent bound on each foreground
channel's mean through the common display pipeline.  This detects systematic
brightness errors that the per-pixel noise tolerance alone permits.
Smooth plastic under constant illumination is checked against independent
Fresnel and diffuse transmission integrals.  Wrong-roughness and darker-base
controls must fail their respective checks.

These cases establish the stated single-surface models and tested lighting
conditions.  General glossy layering, anisotropic roughness, colored-metal
energy compensation, secondary textured paths, and denoising albedo need
further qualification.

== Coating networks

The installed `as_glossy_layer` shader exposes Appleseed's coat closure as
a version 2 network node.  Connect a substrate closure to `in_substrate`
and select its `out_color` output.  For example, start with an optically
neutral coat over an explicitly configured plastic:

[source,tcl]
----
material create coated.material Coated
material set coated.material optical OSL as_glossy_layer
material set coated.material optical OSL.output out_color
material set coated.material optical OSL.version 2
material set coated.material optical OSL.node.base as_plastic
material set coated.material optical OSL.connect.material.in_substrate base.out_outColor
material set coated.material optical OSL.param.in_ior "float 1"
material set coated.material optical OSL.param.base.in_color "color 0.3 0.5 0.7"
material set coated.material optical OSL.param.base.in_specular_color "color 1 1 1"
material set coated.material optical OSL.param.base.in_specular_weight "float 1"
material set coated.material optical OSL.param.base.in_specular_roughness "float 0.35"
material set coated.material optical OSL.param.base.in_scattering "float 1"
material assign ball.r coated.material
----

With an air surrounding medium, index one and zero thickness leave the
substrate unchanged.  Set `in_enable` to `int 0` to bypass a coat regardless
of its other settings.  `in_roughness` selects finite-width GGX reflection;
zero selects an ideal specular event.  `in_reflectance` tints the reflected
coat contribution.  `in_normal` and `in_tangent` set the coat's shading frame.

`in_transmittance` is a scene-linear color defining attenuation per unit of
`in_thickness`.  Thickness is a material optical parameter and does not add
geometry.  Zero thickness disables absorption; a zero transmittance channel
remains exactly zero for positive thickness.  For a matched-index coat,
Beer attenuation uses the normal-projected path once for emitted light and
both incoming and outgoing paths for reflected substrate light.  Coat
attenuation uses the ray's surrounding refractive index.  Each coat can have
its own normal and optical parameters.

Networks support up to four active coats along a substrate path.  A deeper
network fails with an explicit coating-depth diagnostic before an image is
saved or an existing output is replaced.  Renderer closure-count limits also
apply to larger branched networks.

`regress-art-coat` persists and reopens the networks on CSG cubes, flat BOT
cubes, spheres, and ellipsoids under both projections.  Independent emission
references check matched-index Beer absorption, two-pass absorption of a
point-lit diffuse substrate, and smooth Fresnel attenuation.  Additional
cases check smooth reflection against the constant environment, a null coat
over native plastic, a bypassed coat, a zero color channel, different inner
coat normals, and the four-coat boundary.  Disabled absorption must disagree
with its absorbing reference.  The fifth-coat failure must preserve the
previous output byte for byte.

The coat uses Appleseed's layered-BSDF approximation and normal-projected
optical paths.  Finite-roughness attenuation retains its lookup model.
Geometric-film refraction requires additional implementation.  General
nonmatching rough coats, anisotropic coat transport, nested refractive media,
and coated subsurface materials need further
qualification; the listed basic cases do not establish those capabilities.

== Native color-texture decoding

Prefer scene-linear color textures prepared before building mipmaps, with
`as_texture.in_enable_cms` left at `0`.  For an encoded RGB source, the
native node can explicitly decode its sampled values by enabling CMS and
selecting `in_eotf`:

[cols="1,2"]
|===
|Value |Input transfer
|0 |Raw
|1 |sRGB
|2 |Rec.709 inverse camera transfer
|3 |Gamma 2.2
|4 |Gamma 2.4
|5 |Gamma 2.6 (DCI)
|6 |Rec.1886, normalized black and white
|7 |Rec.2020 inverse camera transfer, 12-bit coefficients
|===

For example, select an encoded sRGB color image on a new material:

----
material create color.material "Image color"
material set color.material optical OSL as_plastic
material set color.material optical OSL.version 2
material set color.material optical OSL.node.image as_texture
material set color.material optical OSL.param.image.in_filename "string textures/color.tif"
material set color.material optical OSL.param.image.in_enable_cms "int 1"
material set color.material optical OSL.param.image.in_eotf "int 1"
material set color.material optical OSL.param.image.in_rgb_primaries "string sRGB/Rec.709"
material set color.material optical OSL.param.image.in_workingspace_rgb_primaries "string sRGB/Rec.709"
material set color.material optical OSL.connect.material.in_color image.out_color
material assign ball.r color.material
----

The settings are explicit; file color-space metadata does not select the
transfer.  `in_rgb_primaries` set to `Raw` bypasses conversion of primaries
while retaining the selected transfer.  The decoded `out_channel` uses the
working-space luminance coefficients.  One-channel data images retain
their scalar values, and fill colors bypass decoding.

Decoding happens after the texture lookup.  It cannot correct mipmaps or
interpolation performed on encoded values.  Convert color images to linear
values before filtering when preparing production assets, and retain raw
values for height and normal data.

`regress-art-color` checks all eight transfers against independent linear
RGB reference values, using constant floating-point images and raw
primaries to isolate the transfer.  It checks invalid transfer selections,
CMS bypass, the Rec.709 encoding helper, and the Rec.2020 decoding helper
with both supported coefficient sets.  Checks run in the shader before
display conversion and allow `1e-5` absolute error for float power
approximations.  These tests cover sampled values at the toe and higher
levels; they do not qualify conversions between primaries, HDR and
negative-value handling, or filtering encoded color images.


== Bump and normal-map networks

Version 2 can connect native Appleseed normal nodes to a material.  For
`as_plastic`, the input is `in_bump_normal`.  For example, add a constant
normal-map perturbation to the material above:

----
material set paint.material optical OSL.node.bump as_bump
material set paint.material optical OSL.param.bump.in_mode "string Normal Map"
material set paint.material optical OSL.param.bump.in_normal_map "color 0.85 0.65 1"
material set paint.material optical OSL.connect.material.in_bump_normal bump.out_normal
----

The map stores vector components as data in the range `[0,1]`, decoded to
`[-1,1]`; do not apply a display-color conversion to these components.
The native node's default coordinate system is tangent space.  A neutral
value `(0.5,0.5,1)` preserves the surface normal.  Normals can be chained
through another node's `in_surface_normal` input.  A constant zero bump
value, zero bump depth, and zero normal-map weight preserve that input
normal, including an upstream perturbation.

In tangent space, red follows U and green follows V.  The frame uses the
per-hit U tangent, projected onto the supplied normal's tangent plane; its
orthogonal V axis follows the supplied bitangent's orientation.  This
preserves authored UV mirrors and supports a normal supplied by an upstream
node.  Baked maps must use a matching tangent convention.  Primitives
without mapping derivatives need an explicit frame for controlled
tangent-map orientation.

`in_normal_map_mode` selects `Unsigned` data decoded from `[0,1]` or `Signed`
data in `[-1,1]`.  Values are clamped to that range.  The red and green
flip controls apply after decoding, followed by `in_normal_map_swap_rg`.
The weight mixes the mapped vector with the input normal before
normalization.  A zero or cancelling result, or an unusable projected U
tangent, preserves the input normal.

A missing or zero `Bn` retains the older fixed-cross-product orientation.
For an existing map that needs that convention, connect a zero vector:

----
material set paint.material optical OSL.node.bitangent as_maya_vectorProduct
material set paint.material optical OSL.param.bitangent.in_operation "int 0"
material set paint.material optical OSL.param.bitangent.in_input1 "vector 0 0 0"
material set paint.material optical OSL.connect.bump.Bn bitangent.out_output
----

The regression exercises these native nodes on a sphere and flat and smooth
BOTs.  It requires a tilted normal map to visibly change shading and a
disabled downstream node to match the upstream result.  These checks qualify
network wiring and disabled-node behavior.  `regress-art-normal` also checks
independent analytic frames on flat and smooth BOTs, reflected U/V charts,
spheres, and ellipsoids.  It covers nonzero normal chains, signed/unsigned
encoding, component clamps, channel controls, weighted blends, explicit
frames at small and large scales, and degenerate inputs.

In `Bump` mode, connect a scalar height output to `in_bump_value` and set
`in_bump_depth` in the units of `in_surface_point` (the common-space surface
position by default).  The node retains its signed depth and height
saturation at `[-1,1]`.  Bump mapping changes the shading normal; silhouettes
and CSG boundaries follow the original geometry.

Appleseed now uses a surface-gradient perturbation of the input normal,
preserving smooth BOT normals and previously mapped normals.  A constant
height preserves that normal.  Zero height can still have a nonzero slope
and is evaluated.  Absent or degenerate position footprints preserve the
input normal, and negative depth reverses the perturbation.  The formulation
follows Mikkelsen's _Surface Gradient-Based Bump Mapping Framework_,
https://jcgt.org/published/0009/03/04/[equation (4)].

`regress-art-bump` compares native bump output with independent analytic
normal references on spheres, ellipsoids, Boolean geometry, and flat and
smooth BOTs under orthographic and perspective cameras.  It checks constant
height, affine position-based height, signed depth, a sphere UV height
crossing zero, and missing or collinear footprints.  Scaling both position
and depth by each of `1e-25`, `1e-12`, `1e12`, and `1e25` must preserve the
result.  These checks cover
first-order bump normals, including CSG surfaces without a UV footprint.
LOD transitions, image mapping on other curved primitives, mirrored
geometry transforms, baked per-vertex tangent compatibility, and
secondary-ray behavior still need dedicated qualification.

For an image normal map, prepare a floating-point mipmapped texture without
color conversion, keeping its components as data.  Store it under the
database directory, for example as `textures/normal.tx`.  In MGED:

----
material create normal.material "Image normal map"
material set normal.material optical OSL as_plastic
material set normal.material optical OSL.version 2
material set normal.material optical OSL.node.image as_texture
material set normal.material optical OSL.param.image.in_filename "string textures/normal.tx"
material set normal.material optical OSL.param.image.in_enable_cms "int 0"
material set normal.material optical OSL.node.bump as_bump
material set normal.material optical OSL.param.bump.in_mode "string Normal Map"
material set normal.material optical OSL.connect.bump.in_normal_map image.out_color
material set normal.material optical OSL.connect.material.in_bump_normal bump.out_normal
material assign ball.r normal.material
----

For an image height map, use `Bump` mode and connect `image.out_channel` to
`bump.in_bump_value` instead.  A one-channel image supplies its stored value;
the raw RGB output channel is the mean of the three components.  Set bump
depth in model units.  Leave color management disabled for both kinds of
data, even when the file carries color-space metadata.

`regress-art-texture` uses floating-point one-texel checkers tagged as sRGB
and prepared with box-filtered periodic mipmaps.  Under full minification,
the normal checker averages to neutral `(0.5,0.5,1)` and the height checker
to a constant `0.5`.  Both networks must match the original shading normals
on spheres, ellipsoids, and flat and smooth BOTs, including reflected U/V
charts, in orthographic and perspective views.  Zero-width filtering must
produce a visibly different result for both maps; enabling a display
transfer on normal data must also change the result.  A relocated project
is rendered with the original textures unavailable.  These checks qualify
raw data handling and full minification.

Appleseed uses a lower-left texture origin: increasing U moves right and
increasing V moves upward through the image.  Its texture system flips the
image-row direction, which commonly runs from top to bottom.  This controls
where a normal-map texel is sampled; red and green vector components still
follow the geometry's U/V tangent frame described above.

`regress-art-image-maps` checks spatial sampling independently of renderer
UVs on the fixture's +Z BOT faces.  It reconstructs the authored charts from
position and compares magnified 16-texel linear ramps with native color,
normal-map, and height-map networks under both projections.  It also checks
positive scaling and translation through a native UV placement node,
including image-height gradients carried through the array connection.
A zero-depth control must fail the same height-normal comparison.  The cases
cover clamped linear interpolation, flat and smooth normals, and reflected U/V
charts.  The height reference uses the ramp's known gradient, without
screen derivatives.  A control with the opposite image-row convention must
visibly disagree for all three networks.  These tests establish image
orientation and these BOT magnification paths.

The same regression also reconstructs sphere and ellipsoid longitude and
elevation from position.  Full-range and transformed image maps are checked
under both projections in oblique and near-pole views.  Color and normal
maps use the analytic ramp values and independent tangent frames.  The
transformed height map uses a known analytic spatial gradient.

For full-range height maps, clamping and mip filtering change the slope
near image borders.  The reference measures that filtered slope with
central differences of texture values, holding its analytically derived
footprint fixed.  It does not use texture output derivatives or the native
bump implementation.  A `1/8192` UV step is checked against `1/16384` on the
pole-facing ellipsoid.  These cases validate the sampled height gradients,
including changed slopes at filtered borders; they do not independently
validate the texture library's filtering algorithm.

Dedicated LOD transitions, periodically wrapped seams, exact UV poles,
image mapping on other curved primitives, and compatibility with baked
per-vertex tangent frames remain unqualified.


Native UV placement nodes can feed the image node through a whole
`float[2]` connection.  For example, extend `normal.material` above:

----
material set normal.material optical OSL.param.image.in_interpolation_method "int 2"
material set normal.material optical OSL.node.placement as_max_uv_transform
material set normal.material optical OSL.param.placement.in_tilingU "float 0.5"
material set normal.material optical OSL.param.placement.in_tilingV "float 0.25"
material set normal.material optical OSL.param.placement.in_offsetU "float -0.5"
material set normal.material optical OSL.param.placement.in_offsetV "float -1"
material set normal.material optical OSL.connect.image.in_texture_coords placement.out_outUV
----

This node subtracts the offsets before applying the tiling multipliers and
then wraps coordinates.  The example samples `[0.25,0.75]` in U and
`[0.25,0.5]` in V, away from the image edges.  The regression compares color,
normal, and height results with independent transformed charts on the same
BOTs and projections.  It rejects mismatched array lengths, element types,
scalar/array connections, and unsized inputs before shader execution.
Placement rotation, placement mirroring, and baked tangent-frame changes
remain unqualified.  Literal array assignments are still unsupported.


== Project shader assets

`art` resolves project assets relative to the database directory, including
its `shaders` subdirectory, and also searches the selected Appleseed
`appleseed`, `max`, and `maya` shader libraries.  An installation containing
`shaders/appleseed` beside its `bin` directory supplies these libraries and
its OSL headers relative to the running application.  Development builds
without staged renderer resources use the configured Appleseed prefix.
`regress-art-resources` renders a shader available only in a separate
installation directory, using an independent project-local reference.
This test qualifies resource lookup while retaining build-tree libraries;
it does not establish a self-contained binary distribution.

Build-directory paths and the caller's working directory are
not part of the project convention.  Keep database-relative asset paths
when moving a project to another directory.

For shaders that include Appleseed helper headers, also pass
`"-I$RENDERER_PREFIX/shaders/include"` to `oslc`.  The installed namespace
includes the generated `appleseed/as_osl_extensions.h`.  Keep each `-I`
joined to its directory; this compiler does not consume a separate directory
argument.  The regression compiles a shader through the installed Maya
helper header and renders an extension-function result against an
independent emission reference.

Shader metadata inspection follows the same ordered search paths as OSL
execution.  A same-named compiled shader in the caller's working directory
cannot supply a different interface for a project shader.  The regression
renders with such a collision and compares the result with the independent
texture reference.

For a custom surface shader, save this source as `painted.osl`:

[source,c]
----
surface painted(color in_color = color(1))
{
    Ci = in_color * diffuse(N);
}
----

Compile with the OSL compiler and standard headers from the renderer's
dependency installation.  Here `RENDERER_PREFIX` identifies that installation:

----
mkdir -p shaders
"$RENDERER_PREFIX/bin/oslc" "-I$RENDERER_PREFIX/share/OSL/shaders" \
    -o shaders/painted.oso painted.osl
----

Place the database beside the `shaders` directory.  Select the shader in
MGED, removing the closure-output property because this shader writes `Ci`
directly:

----
material set paint.material optical OSL painted
material remove paint.material optical OSL.output
----

`regress-art` compiles its diffuse shader using the selected dependency
installation and renders it on a sphere, a Boolean solid, and a BOT.  Its
project directory contains spaces and is separate from the rendering
working directory.  A second fixture returns an ordinary color output;
selecting that output as a material closure is rejected before rendering.

== Image-texture preview and minification

Prepare color textures in scene-linear RGB.  A generic OSL `texture()`
lookup uses the stored numeric values; color-space conversion belongs in
asset preparation or an explicit shader operation.  Mipmapped textures
provide reduced-resolution image levels for filtered lookups.  The renderer
dependency installation supplies `maketx`:

----
mkdir -p textures
"$RENDERER_PREFIX/bin/maketx" -d float --filter box --wrap periodic \
    -o textures/wood.tx wood_linear.exr
----

An emission preview exposes texture values independently of scene lighting.
Save this shader as `texture_preview.osl`:

[source,c]
----
surface texture_preview(string in_filename = "", float in_uv_scale = 1)
{
    color texel = texture(in_filename, in_uv_scale * u, in_uv_scale * v,
        "interp", "closest");
    Ci = texel * emission();
}
----

This diagnostic uses nearest interpolation within each mip level.  Mip
selection and anisotropic filtering use the automatic OSL derivatives,
including the UV scaling operation.  Compile and select the preview:

----
"$RENDERER_PREFIX/bin/oslc" "-I$RENDERER_PREFIX/share/OSL/shaders" \
    -o shaders/texture_preview.oso texture_preview.osl
----

In MGED:

----
material create map.material "Texture preview"
material set map.material optical OSL texture_preview
material set map.material optical OSL.version 1
material set map.material optical OSL.param.in_filename "string textures/wood.tx"
material set map.material optical OSL.param.in_uv_scale "float 4"
material assign ball.r map.material
----

Then render with `art -w 512 -n 512 -o preview.png scene.g ball.r`.
Relative texture filenames resolve directly against the database directory.
They do not search the shader-library directories.  Keep textures and compiled shaders with the
database when moving the project.  Paths containing spaces are supported.

`regress-art` generates a one-texel black/white checker and converts it to
floating-point mipmapped data.  Fully minified renders of spheres,
ellipsoids, and flat and smooth authored BOTs must match an independently
shaded linear 0.5 emission reference in orthographic and perspective views.
The comparison bounds both RMS and maximum display-image error.  A control
with zero UV derivatives must differ substantially, establishing that the
check detects missing filtering.  A copied project is also rendered while
the original texture is unavailable, exercising relative asset lookup.
These checks qualify this emission-preview minification workflow; LOD
transitions, color conversion, and alpha need additional coverage.  Native
image bump and normal-map minification is covered separately by
`regress-art-texture`.

`art` enables Appleseed's project-rooted texture lookup for both cached
constant filenames and dynamic filenames.  A same-named file in the
caller's working directory cannot override an asset or supply a missing
project texture.  Explicit absolute filenames retain their meaning.  The
regression checks these cases for 2D lookups and checks constant and dynamic
latitude-longitude environment lookups and both texture-metadata query
variants.  Missing project textures must fail unless the shader explicitly
handles the lookup error and supplies a fallback.

The environment regression also covers a modern OSL compatibility fix:
lookup directions without derivative storage supply zero footprints
instead of dereferencing absent derivatives.

== Validating an installed application

Build the development `art_scene_test` target, then configure the art
regression directory as a standalone test project against the installed
application:

----
cmake -S brlcad/regress/art -B installed-art-tests \
    -DART_INSTALLED_PREFIX="${ART_PREFIX}" \
    -DART_SCENE_TEST="${BRLCAD_BUILD}/regress/art/art_scene_test"
cmake --build installed-art-tests --parallel 2
ctest --test-dir installed-art-tests --parallel 2 --output-on-failure
----

`ART_PREFIX` contains the installed `art`, `oslc`, `maketx`, and `oiiotool`
programs, renderer libraries, and shader resources.  The development helper
creates fixture databases and checks their images.  Shader fixtures compile
with the installed compiler and headers, and all art render commands and
image-texture preparation tools come from the selected installation.
The standalone project shares the regression cases with the development
build and writes its outputs in its own test directory.  If the selected
installation includes `mged`, `art-installed-material` also sources a material
authoring script, inspects its persisted assignment and parameters in a new
art process, and compares the rendered result with a libged-authored
reference.  The project and script paths include spaces.
`art-installed-plate` additionally exercises plate creation and physical
volume conversion through installed mged before checking absorption and
refraction renders.

Loader environment overrides and `BRLCAD_ROOT` are cleared for fixture
compilation and test execution.  On FreeBSD and Linux, the additional
`art-installed-runtime` test audits the dynamically linked application and
tools with `ldd`, including the BOT command plugin when installed.  It
rejects unresolved dependencies, Boost, and libraries outside the
installation and the base system library directories.  It also inspects
these objects and their bundled dependencies with `readelf`, rejecting
absolute runtime search paths, empty entries, and relative paths that escape
the installation.  Runtime logs are saved alongside the test outputs.
Other platforms require their own loader audit before recording a
portable-installation result.

The development `regress-rpath` target separately tests executable and plugin
lookup with conflicting libraries at the configured prefix.  It installs and
moves small fixtures under default, `lib64`, and nested directory layouts,
including paths containing spaces.  Prefix-first controls must select the
conflicting library, while the production relative paths must select the
relocated copy.

Qualify relocation by moving the complete installation to another directory,
including a path containing spaces, and running a fresh standalone test
build against that directory.  Keep database-relative project assets with
their databases.  Record the platform, install configuration, runtime audit,
and regression results with the qualification evidence.  The lower-level
librt and procedural-intersection tests continue to run in the development
build.

== Development milestones

Each milestone requires source changes, documentation, and appropriate
regressions.  A capability is supported only after its complete user path
has passed, including installation and asset lookup where applicable.

. *Design and regression inventory.*  Maintain the responsibility contract
  and capability matrix.  Inventory the useful legacy behavior and create
  small reference scenes.  Exit when each planned feature has a known
  implementation boundary and observable acceptance test.
. *Basic OSL through librt.*  Use a simple diffuse material on a native
  Appleseed mesh, a librt sphere, a Boolean subtraction, and a BOT mesh.
  Isolate shader wiring from intersection behavior.  Exercise multiple
  regions, inherited colors, and explicit shader errors.  Exit when OSL
  shading is demonstrated on all geometry paths with automated checks.
. *Geometry and shading correctness.*  Test full database paths, repeated
  instances, transforms, material inheritance, entry/exit boundaries,
  subtraction normals, back faces, and rays originating inside solids.
  Validate offsets over different model scales.  Define UVs and their
  limitations on primitives, Boolean cut faces, and BOTs; test position-based
  mapping independently.  Validate tangent and differential behavior and
  repeated-render resource ownership.  Exit when diagnostic shaders and
  intersection tests agree with known geometry and threading is reliable.
. *Material authoring.*  Define a versioned representation for shader names,
  typed parameters, networks, connections, assets, and mapping settings.
  Integrate material objects with documented inheritance and override
  precedence.  Preserve useful existing assignments through explicit
  compatibility rules.  Provide command-based creation, inspection,
  validation, modification, saving, and reopening, with examples.  Exit when
  installed applications can reproduce the material workflow independently
  of the build tree and current working directory.
. *Core surface shading.*  Qualify diffuse and glossy reflection, metals,
  glass and absorption, transparency, emission, layering, procedural
  patterns, image textures, and bump/normal mapping.  Test secondary rays,
  nested dielectrics, cavities, thin surfaces, and transmitted shadows.
  Compare emissive surface samples with traced positions, UVs, and normals.
  Expose useful BRL-CAD attributes through renderer services.  Specify color
  spaces and distance units.  Exit when documented materials work on CSG
  and BOT geometry with semantic image checks and defined tolerances.
. *Boost removal.*  Audit declared components before replacing code.  Migrate
  containers and optional values, atomics/time, filesystem, threading, and
  specialized facilities in separate changes.  Combine rendering regressions
  with focused tests of changed path, pattern, and concurrency behavior.
  Exit when the intended renderer build has no Boost build or runtime
  dependency and its regression suite passes, including Windows behavior.
. *Rendering workflow and quality.*  Expose coherent sampling, convergence,
  bounce limits, lighting, environment, camera, and output controls.  Separate
  camera background appearance from environment illumination.  Finish
  supported light translation.  Provide diagnostic AOVs, deliberate color
  management, progress, cancellation, saveview input, framebuffer output,
  repeated frames, and scene/material inspection.  Exit when documented
  commands render representative models reproducibly with useful errors.
. *Advanced capabilities.*  Qualify subsurface scattering, participating
  media, animation/motion blur, additional shader queries, and integrators
  individually against the pinned Appleseed implementation.  Treat true
  displacement separately from bump mapping: displacing exact CSG boundaries
  needs an explicit geometry strategy.  Define overlapping-volume semantics.
  Evaluate MaterialX after the OSL network model is stable, and evaluate TBB
  and Embree through measured requirements.  Exit for each capability requires
  an implementation, examples, tests, and documented limits.  Unresolved
  capabilities remain open milestones.
. *Production qualification.*  Exercise relocatable installed builds on
  FreeBSD, Linux, Windows, and macOS.  Validate shader/compiler compatibility,
  caches, assets, cancellation, cleanup, malformed input, and large scenes.
  Check library precedence with another installation present at the original
  configured prefix; the relocated bundle must use its own libraries.
  Record scene-preparation time, memory, intersections, shader execution, and
  thread scaling before optimizing measured bottlenecks.  Finish user and
  developer documentation and legacy migration guidance.  Exit when fresh
  installations pass the documented workflows and platform results are
  recorded; unavailable platform evidence is not a passing result.

== Validation rules

* Keep small cases with known geometric, material, and visibility answers.
  Pair appropriate cases with native Appleseed scenes to separate renderer
  behavior from the BRL-CAD adapter.
* Compile shader fixtures with the selected OSL compiler and headers.  Check
  renderer diagnostics as well as exit status; an image file alone is not
  proof of successful shader execution.
* Prefer geometric/color/energy bounds for stochastic renders.  Use exact
  pixel comparisons only for controlled deterministic cases.
* Check finite pixels, expected visible regions, material identity, image
  dimensions, output files, and error behavior.  Maintain focused lower-level
  tests for intersection, mapping, filesystem, and threading changes.
* Exercise single-worker and multi-worker rendering and multiple renders in
  one process.  Use sanitizers and resource measurements where supported.
* Preserve meaningful regressions during dependency changes.  Passing a
  narrow shader or mesh test does not establish complete CSG, material,
  installation, or platform support.
