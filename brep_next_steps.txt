NURBS B-REP BOOLEAN NEXT STEPS
=============================

Status: Milestones 1 through 6 complete; continue one failure signature at a time
Updated: 2026-10-27


1. PURPOSE
----------

Improve per-region conversion of BRL-CAD CSG trees into valid, semantically
equivalent NURBS B-Reps while preserving the fail-closed behavior already in
place.  The objective is sustained, measurable improvement on real models,
not a claim that arbitrary NURBS Boolean evaluation can be made infallible.

The production path is `facetize --regions --brep-output`.  It evaluates
regions in persistent crash-isolated workers.  Strict mode publishes no
partial hierarchy; `--tolerate-failures` publishes successful B-Reps while
retaining explicitly marked source CSG for failed regions.

The detailed algorithm and debugging reference is:

  doc/asciidoc/devguides/bool_eval_development.adoc

3. GOALS AND NON-GOALS
----------------------

Goals:

  1. Keep parent-process crashes and invalid published B-Reps at zero.
  2. Convert broad failures into stable, actionable failure signatures.
  3. Increase exact and certified approximate per-region B-Rep coverage.
  4. Preserve semantic fidelity and explicitly retain legitimate thin-volume
     disagreements rather than discarding valid solids.
  5. Bound work, memory, perturbation, and repair displacement.
  6. Make every accepted repair reproducible, transactional, and auditable.
  7. Make corpus changes visible as per-region state transitions.

Non-goals:

  * Do not force a result from ambiguous topology or missing intersections.
  * Do not broaden global tolerances merely to turn failures into successes.
  * Do not delete near-zero-area topology based on area alone; a small face
    may bound a real thin volume.
  * Do not copy Manifold-generated intersection geometry into the B-Rep.
  * Do not expand the Manifold oracle to curved inputs until a shared-edge
    sampling and approximation-tube certificate exists.
  * Do not claim universal support for arbitrary NURBS Booleans.


4. FORWARD-PROGRESS PROCESS
---------------------------

4.1 Record the first failing Boolean node

Every indeterminate evaluation should report a stable stage and reason, the
CSG node path and operation, relevant operand face and edge identities,
tolerances, work counters, retry information, and topology counts before and
after each attempted repair.

Add an opt-in failure snapshot containing the two evaluated operand B-Reps and
the operation at the first failing tree node.  Where needed, include the SSI
triplets and their provenance.  The snapshot must be replayable without the
original database or the rest of its CSG tree.

4.2 Refine the failure taxonomy

Replace `output_not_solid` and `other` with the earliest proved cause.  At
minimum distinguish:

  * missing, duplicate, or incorrectly clipped SSI events;
  * curve-to-surface projection or lift-certification failure;
  * endpoint-cluster or overlap-span inconsistency;
  * unbalanced arrangement incidence or unmatched continuation;
  * incorrect face selection or orientation;
  * unmatched `1:1` or `1:N` edge partitions;
  * missing cap or ambiguous source provenance;
  * valid but nonsolid output after all certified repairs;
  * invalid source geometry, work-budget exhaustion, and timeout.

Improved diagnosis counts as forward progress even before a geometry fix: it
turns a broad failure into a bounded engineering task and prevents unrelated
changes from masking it.

4.3 Minimize and freeze a reproducer

For each common signature, reduce the saved failure to the smallest face pair
or Boolean node that preserves the failure.  Commit that fixture and a focused
test before changing the algorithm.  A repair should address a class of
equivalent failures, not a database object name.

4.4 Implement one vertical fix

Change one failure class at a time.  Perform any topology repair on a copy and
commit it only when all expected invariants improve.  Keep risky algorithms
behind the worker boundary and, where appropriate, behind a shadow or feature
gate until corpus evidence supports enabling them.

4.5 Validate in widening rings

Run, in order:

  1. the minimized unit or replay test;
  2. related intersection, arrangement, assembly, and primitive tests;
  3. the affected M35/Havoc cohort;
  4. the complete M35 hard set;
  5. the full Havoc per-region run; and
  6. the scheduled installed-database matrix under sanitizers.

Use deterministic inputs and repeat numerically sensitive tests enough times
to reveal order or scheduling dependence.  Full-corpus runs should emit a CSV
that can be compared to the checkpoint baseline by component name.


5. ACCEPTANCE GATES
-------------------

A new successful conversion is accepted only when:

  * the output is nonempty when the regularized Boolean is nonempty;
  * `ON_Brep::IsValid()` and `ON_Brep::IsSolid()` pass;
  * topology changes match the repair's declared postconditions;
  * curve and trim lifts remain within their certified tolerance;
  * deterministic Crofton comparison passes, or the result enters one of the
    explicitly bounded thin-divergence retention categories;
  * exact results remain exact, while every perturbation, sampled primitive,
    transform normalization, or ARB repair is marked approximate; and
  * the result and its metadata are stable across repeated runs.

The corpus scorecard is lexicographic:

  1. no parent crashes or invalid published output;
  2. no increase in material semantic mismatches;
  3. no unexplained exact-to-approximate regressions;
  4. fewer generic failures and more specific diagnostics;
  5. more exact or certified approximate successes; and
  6. lower bounded work and runtime for equivalent outcomes.

A higher raw success count does not constitute progress if an earlier gate
regresses.


6. TECHNICAL APPROACH BY FAILURE CLASS
--------------------------------------

6.1 Nonsolid output

Add an edge-accounting ledger before repair.  For every naked edge, record its
source edge or SSI, incident face, traversal, parameter interval, closest
opposite candidate, endpoint error, curve-locus error, and whether the expected
mate is absent or merely partitioned differently.

Address the resulting categories independently:

  * merge only uniquely matching `1:1` edges;
  * normalize tolerance-scale connectors only when their complete locus lies
    in the repair ball;
  * repair `1:N` partitions only with complete monotone interval coverage,
    opposite traversal, valid trim lifts, and unambiguous provenance; and
  * construct a missing cap only from a unique containing source face and a
    certified closed boundary.

All operations remain copy, validate, then publish.

6.2 Unbalanced trim-loop arrangements

Treat imbalance as evidence, not as a condition to patch by adding or deleting
an arbitrary arc.  At every unbalanced node determine whether the cause is:

  * an absent or duplicate intersection event;
  * incorrect overlap interval normalization;
  * an endpoint that should or should not have clustered;
  * a discarded short arc whose endpoint nodes were not merged; or
  * a wrong material-side classification.

Preserve equal incoming and outgoing degree, deterministic maximum-score
continuation matching, complete edge consumption, and closed-loop validation.

6.3 Curve-to-surface projection

Do not independently reconstruct the two parameter curves of a complete SSI
event.  Preserve the model curve and both parameter curves as one triplet.
For genuinely clipped or repaired curves:

  * unwrap periodic parameter domains before fitting;
  * constrain endpoints and known seam or pole representatives;
  * project/fix the whole ordered curve consistently rather than isolated
    samples;
  * adaptively subdivide where the lift error or parameter velocity demands
    it; and
  * certify the lifted curve against the model-space curve over each interval.

If no representative satisfies the tolerance and continuity constraints,
return a projection-specific indeterminate result.

6.4 Degenerate topology and regularization

Use dimensional and topological evidence, not face area alone.  Collapse an
edge or omit an arc only when its full locus is tolerance-bounded and doing so
preserves the intended incidence and material classification.  Retain valid
thin solids even when ray partition conventions disagree at sub-tolerance
scale.

Continue to attempt the exact tree first.  Bounded deterministic perturbation
is a fallback for certified near-coplanar configurations, remains below the
modeling tolerance after all transforms, and records approximate fidelity and
the requested displacement.

6.5 Manifold oracle

Concentrate first on planar/planar interactions.  Build both proxies from the
same sampled SSI vertices and constraints, triangulate exact split-face loops,
and preserve operand and split-face provenance through Manifold.  Accept an
oracle decision only if all output triangles retain recognized provenance and
every new boundary maps to a certified exact SSI.

Develop in shadow mode.  Enable fallback decisions only for a signature whose
focused tests and corpus cohort show no unexplained selection or orientation
disagreements.  Manifold may select exact NURBS face regions and adjacency; it
must not supply final B-Rep curves or vertices.

6.6 Invalid ARBs

Search for the closest valid planar, non-self-intersecting ARB using bounded
reordering and constrained vertex adjustment.  Certify maximum displacement,
planarity, orientation, convex-hull volume change, and the effect of pending
transforms.  Do not simply relax the absolute cap for `s.wind1`; its required
repair currently exceeds that cap.  If no certified repair is sufficiently
close, preserve the source CSG with an invalid-input note.

6.7 Timeouts and work-budget failures

Record candidate-pair counts and time by CCI, CSI, SSI, face splitting,
classification, and assembly.  First add spatial pruning, reuse pair results,
and eliminate repeated retry work.  Increase a budget only when measurements
show bounded legitimate work rather than combinatorial growth.
