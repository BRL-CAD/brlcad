buopt production-readiness checklist
====================================

This checklist records the issues found during the post-rebase review of the
buopt branch.  An item is complete only when the implementation and relevant
tests are both in place.

[x] Make libged command schema/grammar registries safe during static
    initialization and concurrent registration/lookup.
[x] Make semantic-provider initialization and access thread-safe.
[x] Separate semantic candidate values from command-line insertion encoding
    and transient-display escaping.  Cover whitespace, quoting characters,
    Tcl metacharacters, newlines, and terminal control bytes.
[x] Add schema-selectable database-object completion filters.  Ordinary
    geometry roles should exclude _GLOBAL; metadata-aware and binary-object
    commands should explicitly request the broader or specialized sets they
    support.
[x] Make a bare Escape cancel gsh completion without blocking for subsequent
    input bytes.
[x] Honor the completion layout API's character-cell contract for UTF-8,
    including wide and combining characters.
[x] Make MGED terminal cursor positioning safe for wrapped input, and account
    for wrapped input rows in the Tk one-third-prior-output policy.
[x] Repaint gsh transient completion displays when a Windows console resize
    event is received.
[x] Define and enforce safe initialization/lifetime contracts for public
    completion and validation result objects.
[x] Allow qged/libqtcad command completion at an empty prompt.
[x] Reject negative argc in bu_cmd_schema_parse_complete before size_t casts.
[x] Audit and either eliminate or explicitly constrain libged unbound schema
    rows so execution and completion grammars cannot silently drift.
[x] Pass BRL-CAD's repository regression: portable string/file APIs,
    bu_setprogname in test mains, required source headers, and editor footers.
[x] Keep public libbu schema declarations C-only; do not expose C++
    constructors in public C data structures.
[x] Preserve attached short-option arguments (for example, draw -m3) across
    native parsing, validation, option-presence checks, operand counting, and
    option-span analysis.
[x] Preserve draw's established transparency and line-width defaults when
    native options are absent.
[x] Update the GQA plotting test for canonical encoded display-list paths.
[x] Keep non-command database-attribute readers on the supported bu_opt API
    and limit the native-schema source audit to actual command parsers.
[x] Keep independently launched fbserv stress suites from racing for
    overlapping ports while preserving simultaneous worker/server startup;
    report closed-peer writes as failures instead of terminating on SIGPIPE.
[x] Correct MGED's appended Configure binding so GUI initialization does not
    execute a stray closing brace, and exercise GUI binding installation in a
    display-independent Tcl regression test.
[x] Remove the quadratic candidate-validation path from empty database-object
    completion, keep option spellings out of object listings, recognize an
    editable `--` as a long-option prefix, and avoid sorting every possible
    summary refinement during large completion layouts.
[x] Add regression coverage for all corrected behavior and run the full build,
    bu_opt compatibility tests, schema/completion tests, frontend PTY tests,
    available Qt tests, and regress-repository.
[x] Keep bu_opt as the approachable option-authoring API while exposing
    side-effect-free completion and validation inferred from every standard
    bu_opt reader.
[x] Add an ABI-safe per-option sidecar for aliases, custom value types,
    candidates, hints, variable token counts, and context-aware validators.
[x] Add a reentrant builder macro so commands declare familiar option rows
    once and use them for parsing, help, completion, and schema publication.
[x] Add a compact GED option specification for positional roles and command
    constraints, retaining full native schemas and parser-owned grammars only
    for cases that need their additional expressiveness.
[x] Convert representative ordinary, constrained, and context-sensitive GED
    commands (bb, kill, and ls) to the compact facade and preserve hidden,
    type-filtered, alias, and _GLOBAL completion behavior.
[x] Add and registration-time lint a compact positional DSL for ordinary
    option specifications.  Cover cardinalities, GED semantic providers,
    inline keyword vocabularies, inclusive numeric domains, common positive
    and nonnegative domains, and standard color/vector/pattern token shapes.
[x] Survey the remaining full schemas for repeated declarative patterns.
    Keep keyword metadata with aliases/descriptions, command-specific
    validation, heterogeneous repeated groups, subcommand trees, and
    parser-owned languages in native C definitions rather than growing the
    textual facade into a second programming language.
[x] Preserve and test punctuation short options used by legacy commands, and
    make runtime-generated compact schemas own their command names rather than
    relying on registration-call pointer lifetimes.
[x] Identify custom multi-token option values from the parser's structural
    result rather than a fixed backward-search window; cover values wider than
    the built-in color/vector forms.
[x] Reject overflowing option-builder row counts before allocating the
    required terminal descriptor.

Deep tab-completion API and scaling review (2026-08-13)
-------------------------------------------------------

[x] Separate syntax/semantic validation from candidate generation.  A
    validation-only query must not enumerate candidates, and one completion
    request must invoke its selected semantic completer at most once.  The
    public `ged_cmd_validate` API now has that direct behavior; the redundant
    completion-free validation alias was removed.
[x] Remove generic per-candidate reconstruction and whole-command validation.
    Select context-dependent providers once from parsed command state; expose
    an explicit lightweight candidate predicate only for the rare rules whose
    legality actually depends on the proposed value.
[x] Make cursor handling correct in the middle of command, option, quoted,
    escaped, UTF-8, object, and database-path tokens.  Track the full token,
    decoded prefix through the cursor, raw prefix/suffix spans, and the exact
    replacement range separately.
[x] Add deterministic provider-call-count and mid-line replacement tests, plus
    scaling tests which prevent broad object/path completion from regressing
    to quadratic behavior.
[x] Filter database directory entries by type and prefix before sorting,
    encode each matching name once, and avoid a second whole-database search
    for ordinary unescaped hierarchy paths.
[x] Add a database completion index with reliable mutation invalidation so
    root-object prefixes are O(log N + matches), while retaining command-
    selected hidden, _GLOBAL, binary, primitive, combination, and region
    policies.
[x] Add a request-oriented completion API with a candidate budget, total and
    returned counts, truncation state, and independently computed common
    prefix.  Keep a compatibility wrapper for existing callers.
[x] Bound transient-layout work independently of terminal dimensions.  Limit
    materialized candidates and summary-frontier size, precompute UTF-8 widths
    within each layout, retain the candidate set for resize-only repaints, and
    debounce Qt resize rendering.  A 10,000-candidate/100-row regression test
    guards the layout path.
[x] Reuse the cursor parse throughout one completion request, avoid growing-
    prefix revalidation in native schema analysis, and replace recursive
    "copy schema and clear custom_validate" patterns with the explicit
    bu_cmd_schema_validate_syntax API.
[x] Improve experimental API ownership and clarity: const provider data,
    status separate from count, explicit byte-offset terminology, documented
    token-grammar candidate ownership, and removal of result fields duplicated
    by `expected` or `hint`.
[x] Convert the last potentially large composite database provider
    (geometry-or-primitive) and filesystem provider to bounded query
    interfaces, including full-set total/common-prefix metadata.  File
    completion now scans a directory once and retains O(K) rather than O(N)
    candidate storage for a K-entry request.
[x] Keep parser-owned grammar adapters on the same classify-then-enumerate
    path as flat schemas.  Native tree/form adapters and delegated commands
    now use syntax-only validation, search publishes its context-selected
    object provider instead of scanning directly, and custom BREP component
    indices honor the caller's materialization budget while reporting
    full-set count, truncation, and common-prefix metadata.
[x] Keep the compatibility fallback for metadata-free commands on that same
    path: syntax-only validation classifies the object/path role without a
    database scan, and the outer request performs one bounded query.
[x] Keep custom final-value predicates from breaking filesystem navigation or
    bounded extension filtering.  Directory candidates remain available as
    intermediate paths, while graph's SVG role selects an extension-aware
    provider before applying its final-value validator.
[x] Release the allocated NULL-only argv returned by empty command and
    database queries; repeated no-match completion must not leak.
[x] Re-run the full targeted completion/schema/frontend suite, repository
    regression, and measured large-database/layout benchmarks before declaring
    this section complete.

Lower-priority follow-up opportunities
---------------------------------------

These are not recommended as merge blockers.  They are deliberately deferred
because the current measured paths are bounded and the additional abstraction
would be a substantially larger API change without a demonstrated caller need.

* Continue opportunistically migrating schema-backed commands that still
  assemble usage/options prose by hand.  The generator is now the normative
  path; command-specific examples, caveats, and extended explanations should
  be appended after its output rather than restating syntax.  This is ongoing
  maintenance rather than a finite merge-readiness defect.
* A public parsed-command/scan object could share work across separate calls to
  analysis, validation, option-presence, and completion.  Within an individual
  completion request the parse is already shared; most callers make only one of
  these queries, so a public lifetime-bearing object would currently add more
  ownership complexity than saved work.
* Structured candidate records could carry distinct insertion and display
  strings.  Providers currently return values in their declared token grammar
  and frontends own shell/Tcl display encoding.  Introduce records only if a
  provider needs genuinely different insertion and display values; doing it
  speculatively would make every simple provider more verbose.
* Parser-owned languages such as search may eventually expose one inspect tree
  for execution, validation, completion, and JSON.  They are intentionally
  retained as parser-owned grammars today: forcing them into the ordinary
  option schema would duplicate their language or turn the compact schema DSL
  into a general parser generator.
